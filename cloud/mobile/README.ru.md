# Kvist Cloud на телефоне (`/m`)

*(English version: [README.md](README.md))*

Страница Kvist Cloud для телефона: чат с Kvist, сделанный под то, что продаёт облако (часы, машина, которая засыпает и
просыпается, проекты, ключ модели), а не под универсального ассистента. Чёрный и серый, один шрифт, никаких градиентов; цвет
есть только у состояний (работает, готово, ошибка). Простые файлы без сборщика: `cloud/frontend/build.mjs` копирует эту папку в
`dist/mobile`, а сервер отдаёт её по `/m`, `/m/s/<id сессии>` и `/m/p/<id проекта>` (одна страница на все адреса).

За всем этим ночное небо ([`js/stars.js`](js/stars.js)): звёзды со всех сторон вокруг телефона в 3D, нарисованные в родной
плотности пикселей экрана. Телефон как окно в него: повернёшь телефон, и смотришь в другую часть неба (гироскоп; iOS спрашивает
один раз, при первом касании, а iOS-приложение разрешает его странице самого облака), а ближние звёзды медленно плывут мимо
дальних. Без гироскопа вид сам очень медленно поворачивается. Курсор (мышь или палец, пока касается) тоже дотягивается до неба: взгляд
чуть сдвигается за ним, и ближние звёзды скользят относительно дальних, звёзды вокруг расступаются и разгораются, а клик или касание
пускает по ним волну; при «уменьшить движение» небо стоит; скрытая страница не рисует.

Она работает в любом браузере телефона (её можно добавить на главный экран) и внутри приложений для Android и iOS
([`frontends/cloud-android`](../../frontends/cloud-android), [`frontends/cloud-ios`](../../frontends/cloud-ios)), которые
добавляют встроенные платёжные окна операционной системы.

## Экраны

* **Старт** (`/m/`): для чего Kvist, в каком проекте она будет работать, что ещё нужно настроить (тариф, ключ модели, проект) или
  четыре задачи на пробу. Поле ввода прикреплено к низу и никогда не плавает поверх переписки. Первое сообщение улетает коротким «письмом»
  (370 мс, [`js/flight.js`](js/flight.js)): текст складывается, летит на своё место и раскладывается, а слова стартового экрана
  уплывают вверх; касания не блокируются, при «уменьшить движение» анимации нет.
  Пока поле пустое, говорит заголовок посередине ([`js/hints.js`](js/hints.js), тот же файл, что у workspace, где это
  плейсхолдер поля; поле внизу оставляет свою надпись): его слова стираются, фраза печатается по буквам, переносясь
  максимум на две строки (место под обе держится, поэтому ничего не прыгает), стоит
  (первая и все фразы «про сейчас» по 2–3 минуты, остальные иногда только 15–25 с, но не три короткие подряд) и стирается
  быстрыми рывками перед следующей. Фразы «про сейчас» идут через одну, пока условие держится: час, день недели, даты года,
  задачи человека, последний день пробного периода, год с Kvist, первый визит или возвращение после недели; на каждое
  условие три фразы, каждая звучит один раз за визит. Фраза, которая не влезает, пропускается.
  Касание или клавиша в поле останавливают её, фраза стоит целиком; скрытая страница тоже останавливает, а при
  возвращении печатается новая. При «уменьшить движение» фразы меняются целиком.
* **Сессия** (`/m/s/<id>`): твои сообщения, ответы Kvist плоским Markdown и её работа, свёрнутая в одну строку на ход
  («Работала 2 мин · шагов: 6»), которая раскрывается в шаги. Вопрос Kvist (разрешить команду, подтвердить, выбрать) встаёт на место
  поля ввода. Круглая кнопка — *отправить*, а пока Kvist работает и поле пустое — *пауза*.
* **Меню**: сессии по дням или по проектам и полоска аккаунта с оставшимися часами.
* **Листы**: аккаунт (часы, машина, ключ модели, язык), тарифы, оплата, ключ модели (список провайдеров с поиском), новый проект.

## Оплата кошельком телефона

Карту страница не видит никогда. В приложениях она просит у сервера оплату (`POST /api/wallet/checkout`), сервер называет цену и
собирает запрос для окна, приложение открывает с ним Google Pay или Apple Pay и возвращает токен, страница отправляет токен
серверу (`POST /api/wallet/pay`), сервер списывает его через Stripe и засчитывает только то, что подтвердил Stripe
([`wallet.py`](../backend/kvist_cloud/wallet.py)). В обычном браузере кошелька нет, и показываются другие способы оплаты (Platega).

Приложения дают странице `window.KvistHost` (им пользуется только [`js/native.js`](js/native.js)):

| Вызов | Аргументы | Ответ |
| --- | --- | --- |
| `wallets` | | `["google_pay"]`, `["apple_pay"]` или `[]` |
| `pay` | `{wallet, request, environment}` | `{token}`, `{cancelled: true}` или `{error}` |
| `payDone` | `{wallet, ok}` | ничего (окно Apple ждёт его; окно Google закрывается само) |
| `signIn` | | `{started: true}`, когда приложение взяло вход на себя (системный браузер входит, приложение перезагружает страницу уже со входом); `null`: страница входит обычным способом |
| `open` `copy` `share` `haptic` | `{url}` `{text}` `{text}` `{kind}` | ничего |

## Удаление аккаунта

Магазины приложений требуют, чтобы оно было внутри приложения, поэтому оно внизу листа аккаунта и спрашивает дважды. Сервер
([`account.py`](../backend/kvist_cloud/account.py)) выводит человека на всех устройствах, усыпляет машину и выключает продление
тарифа; сам аккаунт стирается через 90 дней (этого ждёт закон). Вход до этого срока отменяет удаление, и страница один раз об этом
говорит. Записи об оплатах остаются, как сказано в политике конфиденциальности.

## В панели IDE

Боковая панель VS Code и JetBrains сверху переключается между «Облако» и «Локально» (переключатель и анимация в
[`frontends/ide/vscode/webview/cloud.tsx`](../../frontends/ide/vscode/webview/cloud.tsx), кривая в три такта: 50, 75 и 30 мс).
Облако там — эта самая страница во фрейме, только поле ввода при фокусе не складывается в одну строку: экранной клавиатуры нет.

Во фрейме нет `KvistHost`, хостом становится панель вокруг: те же вызовы идут через `postMessage`
(`{kvistCloud: {id, name, args}}` вверх, `{kvistCloudReply: {id, result}}` обратно). Отвечает она на `signIn`, `open` и `copy`, на остальное
отвечает `null`. Вход: страница GitHub во фрейме не открывается, поэтому плагин открывает `/auth/app/start?nonce=N&port=P` в системном
браузере, облако отдаёт код слушателю плагина на `http://127.0.0.1:P/signed-in` (RFC 8252), и фрейм меняет код вместе с N на свою cookie.
Это отдельная `kc_ide_session` с `SameSite=None; Secure; Partitioned`: обычная Lax-cookie во фрейм с чужого сайта не приходит. Чужим
сайтам она ничего не даёт: она привязана к верхней странице IDE, API требует `X-Kvist-Client`, websocket проверяет Origin. Только
`/m` разрешает фрейм, и только для `vscode-webview:`, `vscode-file:` и `file:` (страница JCEF); остальной сайт по-прежнему `frame-ancestors 'none'`.
Адрес облака задают `kvist.cloudUrl` в VS Code и `-Dkvist.cloud.url` / `KVIST_CLOUD_URL` в JetBrains; по умолчанию `https://cloud.kvist.site`.

## Тесты

```bash
cd cloud/mobile && npm ci && npm test            # юнит-тесты: Markdown, лента событий, правила, форматы, переводы

# Страница в настоящем браузере против настоящего сервера (tests/server.py: настоящий runner, скриптовый Kvist, поддельный Stripe):
cd cloud/frontend && npm ci && node build.mjs
cd ../mobile && npx playwright install chromium webkit
PYTHON=<python с cloud/backend и cloud/runner> WEBKIT=1 node tests/browser/run.mjs
```

`KVIST_ONLY='<regex>'` запускает часть сценариев, `SHOTS=<папка>` сохраняет скриншот каждого. `PLAYWRIGHT_MODULE` и
`CHROMIUM_EXECUTABLE` указывают на установленный Playwright и браузер. Сценарии проходят первый запуск, вопрос Kvist, паузу,
покупку тарифа каждым кошельком, отклонённую карту и закрытое окно, обычный браузер, русский язык и все ширины телефонов от 320 до
430 px. Workflow [`cloud-mobile.yml`](../../.github/workflows/cloud-mobile.yml) запускает их и тесты обоих приложений, больше
ничего.
