# Политика безопасности

[English version](SECURITY.md)

## Как сообщить об уязвимости

О проблемах безопасности пишите приватно, не в публичном issue. Используйте
GitHub Security Advisories:

<https://github.com/davud-d/Kvist/security/advisories/new>

Укажите, что вы нашли, версию (`kvist --version`), платформу и шаги
воспроизведения. Если проблема позволяет команде или модели обойти песочницу,
шаг подтверждения или правила для секретных файлов, назовите, что именно.

Kvist в стадии beta (0.1.0b1), исправления получает только последний релиз.

## Что считается уязвимостью

Kvist — инструмент под присмотром, а не граница безопасности (см.
[README](README.ru.md#kvist)). В рамках политики:

- способ обойти шаг подтверждения, правила разрешений или политику песочницы в
  executor;
- чтение Kvist файлов, которые она должна скрывать (`.env`, SSH-ключи, сертификаты);
- попадание секрета (ключ API, токен) в лог, файл сессии или запрос к чужому для
  него сервису;
- непредусмотренный исходящий запрос в сравнении с таблицей в разделе
  [Что уходит с вашей машины](README.ru.md#что-уходит-с-вашей-машины).

На Windows и на Linux без Bubblewrap у команд нет сетевой границы; Kvist говорит
об этом при запуске и в каждом подтверждении, поэтому это задокументированное
поведение, а не уязвимость.
