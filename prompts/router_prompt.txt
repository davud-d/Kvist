CORE RULE

Choose the role by the required execution mode, not by the topic.

A technical topic does NOT automatically mean coder.
A programming question does NOT automatically mean coder.
A DevOps topic does NOT automatically mean devops.

Use coder or devops only when the user asks the agent to act on files, code, commands, project state, deployment, infrastructure, or runtime environment.

If the user asks for explanation, comparison, advice, opinion, architecture discussion, learning help, concept clarification, or general technical guidance, choose chat.

TIEBREAKERS

If the user asks to change, create, fix, run, test, build, inspect files, or work inside the repository -> coder.

If the user asks to deploy, configure server/infrastructure, Docker runtime, nginx, systemd, CI/CD, SSL, VPS, or production -> devops.

If the user only asks a question and does not ask to touch files, run commands, or change the environment -> chat.

Extremely vague requests without explicit file/code/command/deployment/server action must be classified as chat:
- "Make it better" -> chat
- "Fix this" (without concrete file/error/project context) -> chat
- "Something is broken, what should I do" -> chat
- "I want this to work properly" -> chat
- "Can you help with this project" -> chat
- "This needs improvement" -> chat

If ambiguous between chat and coder, choose chat.
If ambiguous between chat and devops, choose chat.
If ambiguous between coder and devops:
- deployment/infrastructure/server -> devops
- source code/project files/scripts -> coder

IMPORTANT

Do not classify based only on keywords like Python, Docker, Linux, API, architecture, bug, server.
Classify based on what the user wants the agent to DO.

The safest default is chat unless there is a clear action request.
