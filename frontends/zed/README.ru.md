# frontends/zed/ — Kvist как внешний агент Zed (экспериментально)

⚠️ **Статус: экспериментальная интеграция с ограничениями**

Интеграция Zed работает, но **сильно ограничена публичным API расширений Zed**.
Agent Client Protocol v1 и Extension API Zed не предоставляют многие возможности,
доступные в VS Code и JetBrains. Эта интеграция существует для тех, кто хочет
попробовать Kvist в Zed, понимая её ограничения.

Kvist работает внутри Zed через **Agent Client Protocol**. Это не расширение
Zed: здесь нет `extension.toml` и нет утверждений о каких-либо extension API.
Zed объявил агенты-расширения устаревшими ещё в v1.5.0 и указывает вместо них
на ACP Registry, а запуск собственного агента устроен так: его регистрируют
как [внешний агент](https://zed.dev/docs/ai/external-agents).

| Файл | Что это |
| --- | --- |
| `settings-example.jsonc` | Ровно та запись `agent_servers`, которую нужно вставить в настройки Zed. |
| `README.md` | Этот же документ по-английски. |
| `icon.svg` | Знак 16×16. У `agent_servers` поля иконки нет, поэтому в меню нового потока агент показан только именем. Запись в ACP Registry поле `icon.svg` принимает (рекомендуется 16×16) — знак приготовлен для неё. |

## Установка и запуск

```bash
python scripts/installer/install_cli.py                  # сначала собрать и поставить kvist-core
python scripts/installer/install_zed.py                  # записать одну запись agent_servers
python scripts/installer/install_zed.py --uninstall      # и удалить её обратно
```

`install_zed.py` точечно правит настройки Zed и отказывается писать запись,
указывающую на неустановленный бинарник; см.
[`scripts/installer/README.ru.md`](../../scripts/installer/README.ru.md#как-настраивается-zed).
Zed перечитывает настройки сам — перезапуск не нужен.

Запустить агента вручную:

```bash
/path/to/kvist-core --acp
```

`--acp` говорит JSON-RPC по stdin/stdout. Рабочая папка приходит из ACP
`session/new`, поэтому `--workspace` не используется. `--login` проводит настройку
ключей провайдера в этом терминале и завершается — секреты по соединению ACP
не передаются никогда.

## Как Zed запускает агента

Zed запускает запись `agent_servers` как `<логиновая оболочка> -c '<команда>
<аргументы>'`, где логиновая оболочка — это `$SHELL` (здесь fish). `--no-config`
он не передаёт, и агент передать его не может: обёрточная оболочка успевает
выполнить свой старт и завершить его раньше, чем существует бинарник. (Zed
1.20.2, `crates/agent_servers/src/acp.rs` —
`ShellBuilder::new(&Shell::System, …).non_interactive()`.)

Этот старт пишет в тот же stdout, на котором говорит протокол. Приветствие,
утилита для приглашения или баннер о системе кладут эти байты перед первым
кадром JSON-RPC, и Zed отвергает весь поток как невалидный UTF-8 — в логе
`stream did not contain valid UTF-8`, в уведомлении `response to 'initialize'
never received: oneshot canceled`. Ни то ни другое не называет оболочку: так
выглядит неразбираемый поток.

`env.XDG_CONFIG_HOME` записи указывает на собственный каталог агента, поэтому
обёрточная оболочка не находит ни вашего `config.fish`, ни `config` для загрузки.
Стартовые файлы вашей оболочки не редактируются — они остаются ровно такими же,
и оболочка в любом другом терминале не затронута. fish при первом запуске кладёт
туда свой скелет, который под `fish -c` ничего не выполняет.

Цена в том, что инструменты, которые запускает агент, тоже перестают читать
`~/.config/<tool>/config`. Собственные настройки агента не затронуты: они живут
в `~/.kvist/`, вне XDG.

## Паритет с интеграциями для VS Code и JetBrains

### 1. Полный поведенческий паритет

Поведение одинаково, чем бы хост его ни рисовал:

| Возможность | Примечания |
| --- | --- |
| Весь цикл действий | План, выполнение, обратная связь, завершение. Тот же `LocalAgent`, `SafeExecutor` и хранилище сессий, что и в терминале: ACP — ещё один фронтенд над ними, а не второй агент. |
| Запись файлов | Тот же песочничный контур, та же граница рабочей папки, те же отказы для `.env`/`.kvist`, тот же журнал изменений. |
| Опасные команды и перезапись | Те же правила и исходы. Отказ остаётся отказом; политика проекта не может снять внутренний запрет. |
| Отмена хода | `session/cancel` завершает ход и запечатывает сессию ровно как Ctrl+C в терминале. |
| Идентичность сессии | Идентификаторы сессий стабильны и восстановимы (`рабочая папка` + имя сессии), поэтому вчерашний идентификатор открывается и после перезапуска. Никаких одноразовых UUID. |
| Жизненный цикл сессии | Создание, список, загрузка, продолжение, удаление, закрытие. Продолжение возобновляет разговор, которому принадлежит. |
| Slash-команды | Тот же реестр и те же обработчики, что в терминале и TUI, включая `/commit-message`. |
| Роль, глубина рассуждений | Те же ручки и тот же эффект на прогон. |
| План перед правками | Агент может предложить «сначала план или сразу делать»; предложенный план приходит сообщением, а принять или отклонить его — вопрос с двумя кнопками. |
| Сообщения коммитов | `/commit-message` описывает диф рабочей папки. Он никогда не индексирует, не коммитит и не пушит. |
| Секреты | Ключи вводятся в терминале (`kvist --login`) и хранятся в `~/.kvist/config.json`. Form-elicitation в ACP запрещена для чувствительных данных, поэтому по этому протоколу ключ ни не запрашивается, ни не логируется, ни не попадает в историю сессии. |

### 2. Нативный эквивалент Zed/ACP

Та же возможность, но через ACP и рисуется Zed, а не Kvist:

| Kvist в VS Code / JetBrains | В Zed |
| --- | --- |
| Потоковый ответ чата | Дельты текста в `session/update` |
| Показ рассуждений | Thought-чанки ACP (как их показывать — решает Zed) |
| Предложенный план | Сообщение с Markdown плана (plan-update ACP — список статусов, свободный текст в нём не помещается) |
| Карточки вызовов инструментов | Вызовы инструментов ACP с `ToolKind` и `ToolCallLocation` |
| Живой вывод шелла | Обновления вывода вызова; накопленные снимки сводятся к дельтам |
| Подтверждения, выбор, свободные вопросы | `session/request_permission` и elicitation. Выбор ровно из двух ответов (план сначала или нет, принять план или нет) показывается кнопками разрешения, если у клиента нет form-elicitation; длинный выбор и свободный вопрос требуют form-elicitation, иначе получают отказ. |
| Открыть терминал с Kvist | `/terminal`: `client.create_terminal`, если клиент это умеет, иначе — точная строка команды, чтобы запустили сами |
| Открыть файл из результата | Пути в `ToolCallLocation`, на которые Zed умеет переходить |
| Переключатели роли / усилия / verbose | Session Config Options ACP: `role` (`mode` category), `effort` (`thought_level` category) и `verbose` (булевы или select на старых клиентах) |
| Выбор стиля агента и чата | Session Config Options ACP: `style_agents` и `style_chat` (select с доступными стилями из `prompts/styles/`) |
| Настройки моделей, провайдера, API | Session Config Option `advanced` (меню "⚙️ Advanced") открывает терминал с диалогами `/models`, `/provider`, `/settings-api`, создание custom provider |

### 3. Воспроизвести буквально нельзя — нет публичного API Zed

**Ограничения Extension API Zed — это основная причина, почему интеграция остаётся экспериментальной.**

| Чего нет | Почему | Ближайший нативный эквивалент |
| --- | --- | --- |
| **Строчное дополнение** (`kvist --complete` как ghost text) | `edit_predictions.provider` в Zed принимает только `zed`, `copilot`, `mercury`, `codestral`, `ollama`, `open_ai_compatible_api` или `none` ([Edit Prediction](https://zed.dev/docs/ai/edit-prediction)). Значения для внешнего агента нет, а NES не входит в ACP v1 — он существует только как [RFD](https://agentclientprotocol.com/llms.txt). | Запускать `kvist --complete` из терминала или скрипта. Собственный путь Zed для сторонней модели — сервер с совместимым OpenAI `/v1/completions`; Kvist такого пока не поставляет. |
| **Боковая панель Kvist** (транскрипт, баннер, живая телеметрия) | Нет публичного extension API для произвольной боковой webview ([Extensions](https://zed.dev/docs/extensions) даёт языки, темы, сниппеты, адаптеры отладчика, MCP-серверы). | Собственная панель агента Zed, запитанная от обновлений ACP. |
| **Кнопка сообщения коммита в UI SCM** | Нет публичного API для кнопки в системе контроля версий. | `/commit-message` в панели агента или `kvist --commit-message` в терминале (плагины для VS Code и JetBrains вызывают ту же команду). |
| **Свои карточки, темы и статус-баннер Kvist** | Они живут в терминальном UI, Ink TUI и Electron-GUI. | Отрисовка обновлений ACP в Zed. |
| **Agent Profiles и Skills Zed применительно к Kvist** | Они настраивают встроенных агентов Zed, а не внешних ACP-агентов ([External Agents](https://zed.dev/docs/ai/external-agents)). | `KVIST.md` / `KVIST-CHAT.md` в рабочей папке и промпты стилей. |
| **Настройка провайдера через UI ключей Zed** | Ключи в настройках Zed относятся к моделям Zed, а не к провайдеру внешнего агента. | `kvist --login` или выбор провайдера в терминальном интерфейсе. |
| **Публикация в реестре расширений Zed** | Агенты-расширения объявлены устаревшими ([Agent Server Extensions](https://zed.dev/docs/extensions/agent-servers)); публикация принадлежит ACP Registry, и Kvist туда не выкладывается. | Ручная регистрация из этого каталога. |
| **Аудио- и image-промпты** | В `acp_frontend.py` не реализованы и поэтому не заявлены — `PromptCapabilities(image=False, audio=False)`. | Только текст и пути к файлам. |
| **Next-edit suggestions от агента** | Нет в ACP v1 (см. выше). | Нет. |
| **Плашка закрытой сессии на месте поля ввода** (после `end_session`) | Поле ввода рисует сам Zed; ACP не даёт агенту способа его спрятать или заменить. | Замок ядра: на любой запрос в закрытую сессию приходит фиксированный ответ закрытой сессии и `stopReason: "end_turn"`, до любого вызова модели. Не `refusal`: на него Zed обрезает ленту до сообщения человека ([`acp_thread.rs`](https://github.com/zed-industries/zed/blob/main/crates/acp_thread/src/acp_thread.rs)), и стёрся бы тот самый ответ, который объясняет замок, а ход помечается ошибкой. Новый тред начинает новую сессию. |
| **Автоматический запуск команд в терминале** | `create_terminal` в ACP поддерживает `initial_input`, но Zed может игнорировать его или обрабатывать иначе в зависимости от версии. | Вручную вводить команды в открытом терминале. |

## Что агент заявляет

`acp_frontend.py` объявляет только то, что работает до конца: `load_session`,
список/удаление/закрытие/продолжение сессий, дополнительные каталоги,
встроенный контекст и аутентификацию через терминал. NES, MCP-серверы, модели
провайдеров и аудио- или image-промпты **не** заявляются.
