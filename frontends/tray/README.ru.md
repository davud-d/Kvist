# Kvist tray

Небольшой Electron-фронтенд: одна иконка для всех Kvist, запущенных в терминалах, **внутри твоей панели (бара)**.

- Иконка становится **зелёной**, когда в терминале, на который ты не смотришь, закончился ход, и **жёлтой**, пока ход идёт. Пока ни один Kvist не запущен, иконка скрыта.
- Клик открывает **мини-чат только для чтения**: он разворачивается из иконки, вплотную к бару и поверх остальных окон. Повторный клик закрывает его. Кнопка **Перейти в терминал** поднимает окно терминала (с переключением монитора и воркспейса), и ты продолжаешь в TUI.
- **Отключить иконку** (в панели или в меню трея) выполняет `kvist --tray-op disable`: сохраняет `tray_enabled: false` в `~/.kvist/config.json` и убирает модуль из бара. То же из оболочки: `kvist --tray-op enable|disable|status`.

Иконка включена по умолчанию. Если фронтенд не установлен, иконки просто нет.

## Модуль в баре

Поверх бара на Wayland рисовать нельзя (бар лежит на слое выше обычных окон), поэтому иконка — модуль самого бара. При каждом запуске терминальное ядро вызывает `kernel/tray/tray_bar.py`, который добавляет модуль в найденные конфиги:

| Бар | Конфиг | Место |
|---|---|---|
| Waybar | `~/.config/waybar/config` (или `config.jsonc`) и цвета в `style.css` | `custom/kvist` после первой записи `modules-left`; перезагрузка по `SIGUSR2` |
| Polybar | `~/.config/polybar/config.ini` | `[module/kvist]` после первого модуля `modules-left` первого бара; перезапуск `polybar-msg cmd restart` |

Правка идемпотентна: конфиг, в котором модуль уже назван, больше не меняется, сколько бы ядер ни стартовало (одновременные старты защищает файловая блокировка), а первая версия каждого файла остаётся как `<файл>.kvist-backup`. Polybar, который наследует `modules-left` на втором мониторе, покажет иконку на обоих. Другие бары (i3bar, KDE, GNOME и т. д.) не правятся; тогда демон показывает иконку в системном трее, но никогда обе сразу.

Модуль запускает `kvist --tray-op bar-stream` (печатает состояние) и `kvist --tray-op toggle` (клик). Панель ставится к бару, найденному под курсором в момент клика: поверхность слоя Hyprland (`hyprctl layers`), dock-окно X11 (`xdotool`, `xprop`) или полоса рабочей области дисплея.

## Как это работает

`kernel/tray/tray_link.py` работает в каждом ядре, живущем в терминале (классический REPL и ядро Ink-приложения; ядра, запущенные Electron GUI, ACP или `run_task.py`, не считаются терминальными). В начале и в конце каждого хода оно отправляет демону снимок состояния по loopback TCP. Демон публикует порт и случайный токен в `~/.kvist/tray.json` (права 0600); соединение без токена закрывается. Формат сообщений описан в [UI_API.md](../../docs/UI_API.md#8e-the-tray-link).

Если демон не отвечает, его один раз за процесс запускает первое заметившее это ядро. Блокировка единственного экземпляра гарантирует один демон, даже если несколько терминалов стартуют одновременно. Демон завершается через 30 секунд после отключения последнего ядра.

Транскрипт берётся из `kvist --session-op history` тем же ядром, которое запустило демон (`KVIST_CORE_CMD`). Мини-чат ничего не пишет в сессию.

## Фокус терминала

Предки процесса ядра (ядро, оболочка, эмулятор терминала) сопоставляются с владельцами окон; поднимается ближайший, у которого есть окно.

| Окружение | Нужно |
|---|---|
| Hyprland | `hyprctl` |
| i3 | `xdotool`, `i3-msg` |
| прочий X11 | `xdotool` |
| KDE Wayland | `kdotool` |
| macOS | `osascript` (по возможности, на Mac не проверено) |
| Windows | PowerShell (по возможности) |

Терминал, который обслуживает несколько окон одним процессом (например, `foot --server`), по pid не сопоставить; чат сообщит об этом.

Проверено на i3 с Polybar. Пути Waybar и Hyprland покрыты тестами на примерах данных, но не запускались в живой сессии Hyprland.

## Разработка

```bash
cd frontends/tray
npm install
npm test
npm start          # демон на переднем плане
python scripts/make_icons.py   # пересоздать assets/ (нужен Pillow)
```

Ядро находит демон через `KVIST_TRAY_CMD` (JSON-массив argv) или `node_modules/electron` этого каталога. Python-тесты подставляют в `KVIST_TRAY_CMD` команду, которая сразу завершается, поэтому ни один тест не запускает настоящий демон.
