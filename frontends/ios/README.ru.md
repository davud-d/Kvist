# Kvist для iPhone и iPad

Окно к агенту, который работает на твоём компьютере; идея та же, что у Android-приложения. **На устройстве ничего
не запускается**: приложение показывает компьютеры в твоём Wi-Fi, где работает Kvist, ты нажимаешь на свой,
компьютер один раз спрашивает владельца, и дальше устройство доверенное: оно запускает и переключает сессии,
останавливает агента, отвечает на его запросы (разрешить или запретить команду), вводит `/`-команды и меняет
модель, рассуждение и роль.

*(English version: [README.md](README.md))*

## Одно приложение, две формы

Приложение — тонкая оболочка: веб-вид показывает страницу, которую компьютер отдаёт по адресу `/m/`
(`frontends/web-local/kvist_web/client/mobile/`). Страница сама выбирает форму по окну, в котором она открыта,
поэтому iPad — не растянутый телефон:

| Окно | Что ты получаешь |
| --- | --- |
| iPhone или любое окно уже 700 pt | Один экран за раз: список, потом разговор. Свайп от края возвращает назад. |
| iPad вертикально, Split View, Stage Manager (700–999 pt) | Сессии слева, рядом разговор и **пульт**, который выезжает справа. |
| iPad горизонтально (от 1000 pt в ширину и от 560 pt в высоту) | Три панели сразу: сессии, разговор, пульт. |

**Пульт** — то, на что в телефоне нет места:

- **Ждут тебя** — запрос, который ждёт ответа (команда или diff), в полный размер вместо листа над клавиатурой, и
  другие сессии, которые ждут, в одно касание. Новый запрос сам занимает эту вкладку.
- **Действия** — каждый вызов инструмента в сессии, новые сверху, и весь его вывод рядом со списком.
- **Правки** — что агент изменил в папке (`/diff`), с подсветкой.

С аппаратной клавиатурой: `⌘↵` отправляет, `⌘K` открывает команды, `Esc` закрывает их. Наведение указателя работает.
Поворот iPad, вход в Split View или изменение размера окна в Stage Manager меняют форму, не теряя открытую сессию
(сессия записана в адресе).

Тот же вид получает любой планшет, открывший `/m/`, в том числе Android-приложение (`tablet.css`, `layout.js`,
`desk.js` рядом с `pixel.css`).

## Как это работает

```text
компьютер: запускается любой агент Kvist  ->  ядро поднимает `kvist-web --lan`
iOS-приложение
  1. UDP-зонд на каждый адрес подсети Wi-Fi (и на её broadcast)  ->  компьютер отвечает {id, имя, система, пользователь, порт}
  2. нажатие на компьютер: POST /pair/request  ->  компьютер спрашивает владельца в окне («Разрешить этот телефон?»)
  3. владелец разрешил: устройство получает свой токен  ->  хранится в Keychain (только это устройство), кода вводить не надо
  4. открывает http://<компьютер>:9671/m/ с токеном
```

- Поиск отличается от Android в одном: iOS разрешает приложению слать на один локальный адрес, но не на broadcast
  без права (entitlement), которое Apple выдаёт по заявке. Поэтому приложение шлёт зонд на каждый адрес подсети (не
  больше 1022; большая подсеть обходится вокруг собственного адреса устройства). Маяк на компьютере отвечает любому
  частному адресу, так что там ничего не меняется.
- Экран подключения — файл Android-приложения (`frontends/android/app/src/main/assets/connect.html` и `connect.js`),
  работает без правок: приложение даёт тот же канал сообщений `window.KvistNative`. Стили, спрайты и шрифты берутся из
  веб-клиента при сборке (`scripts/copy-web-assets.sh`).
- Приложение не открывает никаких адресов, кроме доверенного компьютера (`decidePolicyFor`), а каналом сообщений
  пользуются только собственные страницы приложения (origin `kvist-assets://app`), страница компьютера — никогда.
- `KvistCore/` (Swift-пакет, только Foundation и BSD-сокеты) — всё, что не UIKit: поиск, пейринг, правила повторного
  открытия доверенного компьютера и JSON канала сообщений. В `App/` — веб-вид, хранилище в Keychain и обработчик схемы
  для встроенных страниц.
- Работает с компьютером на Linux, macOS или Windows.

## Сборка

Нужен macOS с Xcode 15+ и [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
cd frontends/ios
brew install xcodegen
xcodegen generate                      # создаёт Kvist.xcodeproj (в git его нет)
open Kvist.xcodeproj                   # выбери команду в Signing, запусти на устройстве или в симуляторе
# или из командной строки:
xcodebuild -scheme Kvist -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

На настоящем устройстве первый поиск спросит разрешение искать устройства в локальной сети: разреши.
В симуляторе компьютер — сам Mac (по адресу `127.0.0.1`).

## Тесты

```bash
cd frontends/ios && swift test         # KvistCore: macOS или Linux с тулчейном Swift 5.9+
scripts/live-check.sh                  # тот же код против настоящего маяка и сервера пейринга kvist-web на loopback
```

`swift test` работает и на Linux (хватит контейнера `swift:6.0`), включая настоящий обмен по UDP. Живая проверка
запускает собственные маяк и HTTP-сервер `kvist_web` из репозитория (окно владельца заменено на «да») и прогоняет
через Swift-код по настоящим сокетам и `URLSession` цепочку: поиск → пейринг → повторное открытие с сохранённым
токеном → «забыт» → недоступен (`SWIFT_IN_PODMAN=<образ>` запускает Swift-часть в контейнере).
