# веб-клиент kvist: спека редизайна

## рамки
- меняем только frontends/web-local/kvist_web/client/ и tests/browser/. ядро, ssh/, bridge/, runtime/, electron, image-attachments.js не трогаем.
- единственные правки вне client/ и tests/browser/: исключение для сервера и строки package-data для новых файлов клиента в pyproject.toml (fonts/*.woff2, fonts/OFL.txt, features/feed.js и далее).
- исключение для сервера: .woff2 в белом списке /assets/* (http_api.py:256) и одна строка mimetypes.add_type("font/woff2", ".woff2") (http_api.py:24), потому что python до 3.14 знает .woff2 только через системный mime.types, которого может не быть. csp не расширяется.
- единственная правка ядра: журнал сессии берёт тот же stream_id, что живой поток (kernel/session_events.py, kernel/event_stream_ui.py, коммит 823ddda), иначе ответ из стрима и из истории не склеиваются по stream_id. поля событий и версия протокола не менялись.
- без фреймворков и сборки: чистые es-модули, csp script-src 'self' остаётся. внешних шрифтов и cdn нет, инструмент работает офлайн.
- только тёмная тема. цвета заводим токенами, чтобы светлую тему потом добавить заменой набора.
- /assets/* отдаёт только .js .css .svg .png и .woff2 (font/woff2). webp и другие форматы не использовать.
- фикс дельт стрима уже в main (a1b1dbf). его не переделываем, reducer должен с ним совпадать.

## принципы
1. плоский фон. без градиентов, теней, свечения, blur, стекла. удалить --glass-*, --bg-subtle, cursor glow.
2. один акцент. он стоит только на: активная сессия, фокус поля ввода, кнопка отправки, непрочитанное, активная вкладка, выбранное состояние радио и флажка (accent-color), рамка панели запроса, пока фокус не внутри неё, кольцо фокуса контрола.
3. рамка есть только там, где она что-то разделяет.
4. плотность: строка сайдбара 28px, ui 13px, текст ответа 14px/1.55, mono 12.5px.
5. движение, отвечающее на действие пользователя, нужно; декоративное запрещено. при смене вида контейнер ленты проявляется целиком, блоки при загрузке и смене сессии не анимируются. анимируются только opacity и transform; два исключения, оба grid-template-rows от 0fr к 1fr: группа в сайдбаре и раскрытие вывода (вызов, группа вызовов, мысль). width, height, margin, top и left не анимируются нигде, will-change постоянно не ставится. длительности и кривая это токены (раздел «движение»). prefers-reduced-motion выключает все transition и animation, появление и скрытие мгновенные.
6. антишаблон. text-transform: uppercase запрещён. цепочек "a · b · c" в нижней строке и шапке нет, элементы разделяет отступ. подписи над блоками только там, где без них блок непонятен. mono только для кода, путей, вывода инструментов, строк notice и статусной строки; остальной текст (заголовки, подписи, селектор модели) идёт шрифтом --sans.
7. оранжевый цвет только у белки. других тёплых акцентов в интерфейсе нет: --warn жёлтый, --err красный, --accent голубой.

## токены
один блок :root. все цвета в oklch. остальной css не содержит цветовых литералов, кроме transparent и currentColor. значения стартовые, финал подбираем на макете.
- фон: --bg-0 oklch(19.9% 0.011 260.7) страница, --bg-1 oklch(23.3% 0.011 254.1) панели, --bg-2 oklch(27.5% 0.015 256.8) приподнятое и hover. стартовые значения получены переводом прежних hsl скриптом на node.
- линии: --line oklch(31.5% 0.017 255.6) разделители без требований к контрасту, --line-strong oklch(56% 0.022 253.5) граница поля ввода и полоса user-блока. светлота --line-strong поднята с 39% до 56%, иначе контраст 1.55:1 на --bg-2.
- текст: --text oklch(92.1% 0.006 255.5), --text-2 oklch(74.2% 0.016 257.2), --text-3 oklch(65.7% 0.017 257.2).
- акцент: --accent oklch(76% 0.12 224). оттенок 224 взят скриптом с голубой (светлой) полосы шарфа белки, светлота 0.70-0.80 в кадрах frontends/tui/ink/mascot/frames/; тёмно-синее тело шарфа даёт 260. chroma 0.12 стартовая. оттенки через color-mix(in srgb, var(--accent) 14%, transparent)
- статусы: --ok oklch(74% 0.14 150), --warn oklch(74% 0.14 95), --err oklch(74% 0.14 22). светлота и chroma общие, различаются оттенком. --warn жёлтый, не оранжевый. статус не передаётся одним цветом: рядом всегда форма (кольцо, точка, галочка, крестик) или текст.
- радиус: --r 4px, поле ввода 6px
- движение: --dur-fast 100ms, --dur-base 160ms, --dur-slow 240ms, --ease cubic-bezier(.2, .8, .2, 1). значения стартовые. цветов и теней движение не добавляет.
- шрифты: --sans системный стек. --mono JetBrains Mono (self-hosted, client/fonts/JetBrainsMono.woff2, лицензия client/fonts/OFL.txt), запасной ui-monospace. внешних адресов нет, @font-face с font-display: swap. файл с кириллицей и латиницей, переменная толщина 400-600; если он не влезает в лимит 120 КБ, два файла (Regular, Medium), подрезанные pyftsubset до латиницы, кириллицы, пунктуации и псевдографики. источник: официальный релиз github.com/JetBrains/JetBrainsMono, лицензия сверяется с файлом из релиза.
- рамки: исключение для сервера описано в разделе «рамки». csp не расширяется.

### контраст
расчёт по WCAG, проверка против --bg-0, --bg-1 и --bg-2 (все три фона).
- текст (--text, --text-2, --text-3, а также --accent, --ok, --warn, --err там, где они красят текст) не ниже 4.5:1.
- не текст не ниже 3:1: граница поля ввода, кольца фокуса и спиннера, точки индикаторов, --line-strong.
- граница поля ввода это --line-strong. отдельный токен заводится, только если --line-strong не проходит; цветовых токенов не больше 14.

## лента: блоки
один тип блока, один рендер. рамок и аватаров нет, подписи "You" и "Kvist" убрать (они остаются только для скринридера).
- user: сообщение попадает в ленту в момент отправки, не после запроса истории (синтетическое событие client.user_sent, блок с local: 'sending'); запись user журнала с тем же текстом заменяет первый такой блок на месте, id блока (ключ строки) и DOM-узел те же, повторной анимации нет; "sending" вида не имеет. если POST отправки вернул ошибку, блок получает "Not sent" и кнопку Retry, текст остаётся в блоке и в поле ввода не возвращается; Retry шлёт тот же блок, при успехе сообщение одно. сообщение с вложениями локального блока не имеет: журнал дописывает к тексту метки [Image #N], и сопоставить по тексту нельзя. локальный блок живёт только в памяти страницы: после перезагрузки лента это журнал. полоса 2px --line-strong слева, без заливки и рамки. миниатюры вложений не рисуются: событие user в журнале хранит только текст с метками [Image #N] (agent.py:569), данных картинок в нём нет.
- text: события message, final, plan, stream_*. markdown без рамки. стрим рисуется тем же markdown-рендером, что и готовый ответ, поэтому stream_commit не меняет высоту блока (было 207px при 1440px). plan получает подпись "plan" 11px --sans --text-3, строчными.
- reasoning: события reasoning_*. строка --sans 13px: "thinking Ns", пока идёт стрим, и "thought for Ns" после (без секунд, если журнал записал 0). мысль, которая закончилась быстрее секунды и не принесла текста, строки не получает: "thought for 0.0s" в ленте нет. мысль с текстом или в секунду и дольше остаётся со своей подписью. summary --text-3, тело --text-2, тоже 13px --sans. перед summary шеврон 10px (svg, currentColor), он поворачивается на четверть при открытии и скрыт у мысли без текста. левый край содержимого summary как у остальных блоков колонки, текст summary стоит после шеврона (12px и отступ 8px), тело с тем же отступом под текстом. шеврон один на reasoning, tool и группу (feed.js chevron(), css .chevron). с шага 3d summary у tool и reasoning шире колонки на --row-pad (6px) с каждой стороны и с таким же padding: содержимое осталось на краю колонки, а кольцо фокуса лежит внутри бокса. свёрнута, раскрывается по клику, Enter и Space до текста мысли. секунды тикают от startedAt (ts reasoning_start), один setInterval на feed раз в секунду, он живёт только пока есть блок со streaming и очищается после; в reducer тиков нет. журнал хранит текст мысли целиком (до 20 000 символов) и duration_seconds, но пишет start, chunk и commit вместе в момент коммита, поэтому живые reasoning_* reducer принимает сам (как stream_start), а запись журнала находит блок по stream_id и ставит его на место. мысль без текста не раскрывается и тела не рисует.
- tool: события step, action_result, action_output, связь по call_id. строка 24px mono 12.5px: слева статус формой (running кольцо 12px с вращением, ok галочка, failed крестик), затем шеврон (только если у вызова есть вывод или summary для раскрытия), имя действия из TOOL_NAMES (--text, вес 500: оно ярче цели), цель (--text-3, одна строка). путь (есть "/" и нет пробелов) режется по последнему "/": имя файла и его родитель остаются целыми, а при нехватке ширины обрезается начало директории многоточием слева (.tool-dir, direction: rtl, внутри bdi; .tool-file не сжимается), весь путь лежит в title. команда и всё остальное режется с конца до 80 символов (.tool-text). toolTarget возвращает { dir, name, full }, справа exit_code, если он не 0, и время (step до action_result, formatDuration). время показывается, если вызов шёл 2 с и больше (по миллисекундам) или упал; быстрый успешный вызов времени не показывает. цель берётся из step и остаётся после результата. вывод раскрывается кликом, Enter и Space (нативный details), mono, max-height 320px с прокруткой; закрыт по умолчанию, у failed с выводом открыт. ручное переключение сильнее умолчания, его хранит feed в Map по ключу блока, не reducer. шеврон только при выводе: строка без вывода и без summary не details по поведению (класс tool-static: без шеврона, без hover, без cursor: pointer, tabindex -1, клик не раскрывает), её метка стоит в той же колонке, что у строк с шевроном. у строки с выводом hover фон --bg-2 и cursor pointer. фокус с клавиатуры: кольцо 2px --accent внутри summary (outline-offset -2px, радиус --r), его не обрезают content-visibility строки и блок вывода под ней.
- группа: вызовы с общим batch_id при двух и более вызовах собираются в строку-заголовок: статус формой (running, если идёт любой вызов, иначе failed, если упал любой, иначе ok), шеврон, текст "N calls" (--text-2, вес 400) и состав: уникальные названия действий через запятую в порядке появления ("Read, Search, Bash"), --text-3, с многоточием, полный список в title. если в группе есть упавшие вызовы, текст "N calls, M failed", часть "M failed" цветом --err. время группы от первого step до последнего результата, по тому же правилу, что у вызова (от 2 с или у упавшей группы); вызовы внутри с отступом 16px. свёрнута, если все вызовы ok и ход закончен (turn_end или выход процесса), иначе развёрнута.

## движение
движение отвечает на действие пользователя; декоративного нет. всё идёт через токены (--dur-fast, --dur-base, --ease), client/utils/motion.js читает их при старте анимации. при prefers-reduced-motion и в скрытой вкладке motion.js ничего не запускает (вызывающий показывает или скрывает сразу), в CSS один блок prefers-reduced-motion выключает все transition и animation.
- hover, focus-visible и active у кнопок, строк, вкладок, групп и полей: transition только color, background-color, border-color и opacity, --dur-fast. кнопка отправки на :active scale(.96), шеврон поворачивается за --dur-fast.
- смена вида: при смене выбранной сессии, создании новой и первой загрузке страницы контейнер ленты (#conversation) проявляется целиком: opacity, --dur-base, element.animate на контейнере, без таймеров на блок. анимация стартует после того, как пришла история, лента отрисована и прокручена вниз; быстрая смена отменяет прежнюю анимацию. пустое состояние проявляется так же. сдвига translateY у контейнера нет: с ним самый длинный кадр смены на 300 tool-строк был 66.6 ms (больше линии 50 ms), остался opacity. блоки внутри при загрузке и смене сессии не анимируются.
- блоки, добавленные живьём после первой отрисовки: сообщение пользователя opacity и translateY от 4px, --dur-base; блоки агента (text, tool, reasoning, notice) только opacity. при восстановлении из истории, смене сессии, document.hidden и при добавлении больше пяти блоков в одном кадре блоки не анимируются (feed.render получает признак live, session.js передаёт его только после первой отрисовки сессии).
- оверлеи (модалка, палитра команд, инструменты сессии): открытие opacity у подложки и opacity с translateY от 8px у карточки, --dur-base; закрытие --dur-fast, элемент скрывается по animation.finished, а не по таймеру; повторное открытие во время закрытия отменяет закрытие. шторка сайдбара на узком окне: translateX и подложка opacity, открытие --dur-base, закрытие --dur-fast, класс sidebar-open снимается по animation.finished. других меню в клиенте нет.
- появление за --dur-base: баннер закрытой сессии (opacity), панель вопроса (opacity, translateY 8px), "Jump to latest" (opacity, translateY 4px, centring translateX(-50%) остаётся), строка новой сессии в сайдбаре (opacity). смена вкладки Files, Diff, Terminal: содержимое проявляется opacity за --dur-fast (открытие самого вида содержимое не анимирует). Send и Stop: тот, что занимает место, проявляется за --dur-fast, ушедший пропадает сразу.
- два роста размера, только grid-template-rows от 0fr к 1fr, --dur-base, обёртка .fold > .fold-inner (overflow hidden, min-height 0): раскрытие группы в сайдбаре и раскрытие вывода вызова, группы вызовов и мысли. рост запускает только клик человека (класс .fold-enter перед открытием details, снимается по событию toggle); раскрытие самой лентой (упавший вызов, развёрнутая группа) и любое закрытие мгновенные. состояния раскрытия живут в feed.userOpen и при перерисовке не сбрасываются. проверено в Chromium 153; Firefox (Playwright) не установлен, не проверялось.
- ограничения: цветовые литералы и box-shadow вне :root запрещены (как и раньше), will-change нигде.

## reducer
- client/features/blocks.js, чистая функция reduce(state, envelope) без dom, без глобального состояния, без часов и случайности. envelope: {seq?, ts?, durable?, event}.
- через неё идут и живой sse, и восстановление из /api/v1/history.
- в reducer живут: склейка stream_chunk и reasoning_chunk (append=true добавляет дельту, append=false или отсутствие поля заменяет текст, stream_commit ставит финальный), связь по call_id, группы по batch_id, секунды reasoning, дедупликация по seq, синтетические события клиента (client.input_answered, client.inputs_closed, client.session_closed и client.user_sent, user_failed, user_retry, user_unsent: слияние локального блока user с записью журнала), время вызова (startedAt от ts step, endedAt от ts action_result; ts 0 журнала это не время) и признак turnEnded у блоков tool после turn_end.
- тесты: node --test, frontends/web-local/tests/client/blocks.test.mjs, без браузера. кейсы: дельты стрима, снимок при append=false, дельты reasoning, commit. сценарий стрима в redesign.mjs остаётся.
- client/features/feed.js рисует блоки по ключу блока и обновляет только изменённые; раскрытые блоки не схлопываются при пришедшем событии.
- состояния ленты проверяет tests/browser/feed-states.mjs: готовые последовательности событий через blocks.js и feed.js, подгруженные со страницы (/assets/features/*.js), снимки 1440x900 и 390x844.
