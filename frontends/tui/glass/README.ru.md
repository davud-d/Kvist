# Kvist Classic

Пользователь видит этот интерфейс как **Classic**; папка, крейт, `kvist-glass`,
значение фронтенда `glass` и `KVIST_GLASS` сохраняют рабочее имя Glass.

Терминальный интерфейс поверх фотографии: разговор лежит на карточках из
матового стекла, изменённые файлы и помощницы слева, живое превью браузера
агента справа. Написан на Rust (ratatui + crossterm), картинки выводятся
через графический протокол kitty. Ядро Kvist запускается дочерним процессом в
режиме `--frontend stdio-multi` (`docs/UI_API.md` §8c).

**Состояние: прототип, подключённый к ядру.** Лаунчер запускает его как один
из терминальных интерфейсов: `kvist --frontend glass` или выбор через `/tui`
(в Ink, Classic Legacy или в самом Classic), после чего он открывается при каждом
запуске. В терминале, где он не может рисовать, или без сборки лаунчер говорит
почему и открывает Ink.

## Какие терминалы

Интерфейс держится на картинках, поэтому нужны **графический протокол kitty**
и размер ячейки в пикселях:

| Терминал | Работает |
|---|---|
| kitty 0.28 и новее | да (проверено на 0.49) |
| Ghostty | должен (протокол kitty), ещё не проверялся |
| WezTerm, Konsole | не проверялись: протокол kitty они поддерживают не полностью |
| Alacritty, GNOME Terminal, Windows Terminal, xterm | нет |
| что угодно внутри tmux, GNU screen или Zellij | нет: мультиплексор не пропускает картинки |

В любом другом терминале программа **не запускается**. Она проверяет терминал
до того, как занять экран, пишет причину и что делать вместо этого и выходит
с кодом 3. `kvist-glass --check` выполняет только эту проверку (код 0 значит,
что запуск возможен), так что лаунчер может решить заранее, ничего не запуская.

## Запуск

Установщик собирает его в бинарник `kvist`: отметь «Rust toolchain» и «CLI» в
`python scripts/installer/install.py` (Linux и macOS); релизные сборки тоже его
содержат. Вручную:

```bash
cd frontends/tui/glass && cargo build --release   # лаунчер найдёт target/release/kvist-glass
kvist --frontend glass                              # или /tui glass, сохраняется на следующие запуски
```

Лаунчер ищет `KVIST_GLASS`, затем `kvist-glass` в PATH, затем сборку этой
рабочей копии, и передаёт своё ядро в `KVIST_CORE_CMD`. При прямом запуске
`kvist-glass --workspace /путь/к/проекту` берётся ядро рабочей копии.

- Ядро берётся из `KVIST_CORE_CMD` (JSON-массив строк, как его передаёт
  лаунчер Ink-приложению), иначе из этой рабочей копии:
  `.venv/bin/python kernel/__main__.py`. Его stderr пишется в
  `kvist-glass-core-<pid>.log` во временной папке; журнал удаляется, если ядро
  завершилось чисто, и остаётся в остальных случаях.
- Фотография показывается одна, пока ядро не пришлёт `hello` (около 10–15 с,
  в основном ядро загружает списки моделей). Если ядро не запустилось, там же
  видна причина и путь к журналу.
- Смену провайдера и моделей ядро сохраняет, как и везде. Чтобы попробовать,
  не трогая свои настройки, укажи в `KVIST_CONFIG_DIR` копию `~/.kvist`.
- `KVIST_GLASS_FPS` задаёт частоту кадров, пока что-то движется (по умолчанию
  60, от 20 до 240; другое значение останавливает запуск с объяснением). Ставь
  частоту своего монитора: kitty показывает не чаще неё (`sync_to_monitor`) и
  не больше 100 кадров при своём `repaint_delay 10` по умолчанию. Анимации
  отмеряются в миллисекундах, поэтому частота меняет плавность, но не
  скорость. Когда ничего не движется, экран перерисовывается раз в 90 мс, а
  ввод рисуется сразу.
- Язык берётся из `KVIST_LANG`, затем из `LC_ALL` / `LANG` (`ru` или английский).

## Клавиши и мышь

Главные действия на клавиатуре; панели, превью и списки выбора открываются и
мышью.

| Клавиша | Мышь | Что делает |
|---|---|---|
| Enter | | отправить (Shift+Enter или Alt+Enter: новая строка) |
| ↑ / ↓ | | сдвинуть курсор на строку с сохранением колонки; на первой или последней строке — в начало или конец текста, а дальше ↑ листает прежние вводы (рабочей папки, их хранит ядро), ↓ возвращает вперёд к черновику |
| `/` | | открыть список команд; набор сужает его до имён, которые начинаются с введённого |
| ↑ / ↓ в списке | наведение | выбрать команду (по кругу) |
| Tab в списке | | дополнить выбранное имя (`/style `) и вводить аргументы |
| Enter в списке | клик по строке | выполнить выбранную команду, а не набранное начало; `/rename` только дополняется, ему нужно имя |
| `/имя аргументы` + Enter | | команда ядра (`/provider`, `/models`, `/role`, `/effort`, `/new`…) |
| Ctrl+P | клик по модели в строке состояния | выбрать модель любого подключённого провайдера |
| | клик по провайдеру в строке состояния | выбрать провайдера (`/provider`) |
| `/tui` + Enter | | выбрать терминальный интерфейс; лаунчер запустит его сейчас и в следующие разы |
| Esc, Esc | | остановить идущий ход (после первого Esc видно, что сделает второй) |
| | клик по превью браузера | открыть браузер в центре; Esc закрывает |
| Ctrl+T | клик по «Помощницы» или по помощнице | открыть панель помощниц; Esc закрывает |
| PageUp / PageDown | колесо | прокрутить разговор |
| Ctrl+C | | выйти |

Ответы агента рисуются как Markdown (pulldown-cmark): заголовки, вложенные
списки, цитаты, линии, ссылки с адресом, чек-листы, таблицы и блоки кода с
подсветкой синтаксиса (syntect с грамматиками two-face: TypeScript, TOML,
GLSL и другие). Одиночный перенос строки в ответе остаётся переносом. Курсор
ввода — собственная мигающая черта терминала цвета лунного света (OSC 12).

Ctrl+P показывает модели всех подключённых провайдеров (команда ядра
`catalog`: сохранён ключ или вход, живой список моделей) под именем
провайдера, текущий отмечен. Tab переключает, какую модель выбираешь: умную
или быструю; печатай для фильтра. Модель другого провайдера переключает и
провайдера, а вторая роль берёт модель, которая у этого провайдера уже
выбрана (`models PROVIDER FAST SMART`, одна пересборка).

Любой вопрос ядра (выбор, текст, ключ, подтверждение) открывает один и тот же
стеклянный диалог: печатай, чтобы отфильтровать список, стрелки и Enter для
ответа, Esc для отмены. Одобрение команды показывает саму команду и оценку
риска от ядра; ответы «Да», «Всегда» (только когда ядро предлагает запомнить
шаблон) и «Нет», заранее выбрано «Нет». Закрытая сессия заменяет поле ввода
текстом ядра и одной кнопкой «Новая сессия» (`/new`); Enter делает то же.

## Как это рисуется

- `backdrop.rs` подгоняет фотографию под окно в полном разрешении и в
  фоновом потоке готовит четыре её размытые и более тёмные версии.
- Каждая карточка — отдельная картинка: вырезка размытой фотографии под ней,
  тонированная, со сглаженными скруглёнными углами и тонким бликом по краю.
  Карточки ездят перемещением размещения с пиксельным смещением, поэтому
  движение плавнее одной ячейки.
- Картинка загружается один раз (файлом в `/dev/shm`, если терминал это
  принимает, иначе сжатой прямо в поток), дальше её только размещают,
  двигают и убирают. При открытии диалога фон переключается между заранее
  загруженными уровнями размытия.
- Превью браузера — событие ядра `screen`: `screen.rs` забирает его
  `frame_url` (только локальный адрес) примерно раз в секунду.
- Движения идут по кривой «рывок» (`anim.rs`): медленный старт, короткая
  быстрая середина и долгое мягкое торможение (на 600 мс примерно 200, 50 и
  350 мс). Открытие браузера и появление превью вместо этого слегка
  перелетают цель.
- Текст — обычные ячейки поверх картинок. Картинки лежат под ячейками с цветом
  фона, поэтому подсвеченная строка закрывает стекло.
- Собственный отступ терминала закрашивается цветом краёв фотографии (OSC 11)
  и возвращается при выходе (OSC 111).

## Что приходит из ядра

- Добавленные и удалённые строки по файлам берутся из `action_result`
  (`lines_added`, `lines_removed`): это построчный дифф самого исполнителя.
- Панель помощниц показывает вызовы каждой помощницы по ходу работы с концом
  их вывода (`helper_activity`); левая карточка показывает, чем помощница
  занята сейчас.
- После `/session` лента заполняется заново из журнала сессии
  (`--session-op history`, последние 500 событий). Вызовы и помощницы, которые
  журнал не довёл до конца, показаны остановленными, а если более ранние события
  не поместились, всплывает уведомление.
