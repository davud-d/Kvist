# Kvist Classic

Пользователь видит этот интерфейс как **Classic**; папка, крейт, `kvist-glass`,
значение фронтенда `glass` и `KVIST_GLASS` сохраняют рабочее имя Glass.

Терминальный интерфейс поверх зацикленного видео леса: разговор лежит на карточках из
матового стекла, изменённые файлы и помощницы слева, живое превью браузера
агента справа. Написан на Rust (ratatui + crossterm), картинки выводятся
через графический протокол kitty. Ядро Kvist запускается дочерним процессом в
режиме `--frontend stdio-multi` (`docs/UI_API.md` §8c).

**Состояние: прототип, подключённый к ядру.** Лаунчер запускает его как один
из терминальных интерфейсов: `kvist --frontend glass` или выбор через `/tui`
(в Ink, Classic Legacy или в самом Classic), после чего он открывается при каждом
запуске. В терминале, где он не может рисовать, или без сборки лаунчер говорит
почему и открывает Ink.

## Какие терминалы

Интерфейс держится на картинках, поэтому нужны **графический протокол kitty**
и размер ячейки в пикселях:

| Терминал | Работает |
|---|---|
| kitty 0.28 и новее | да (проверено на 0.49) |
| Ghostty | да (проверено) |
| WezTerm, Konsole | не проверялись: протокол kitty они поддерживают не полностью |
| Alacritty, GNOME Terminal, Windows Terminal, xterm | нет |
| что угодно внутри tmux, GNU screen или Zellij | нет: мультиплексор не пропускает картинки |

В любом другом терминале программа **не запускается**. Она проверяет терминал
до того, как занять экран, пишет причину и что делать вместо этого и выходит
с кодом 3. `kvist-glass --check` выполняет только эту проверку (код 0 значит,
что запуск возможен), так что лаунчер может решить заранее, ничего не запуская.

## Запуск

Установщик собирает его в бинарник `kvist`: отметь «Rust toolchain» и «CLI» в
`python scripts/installer/install.py` (Linux и macOS); релизные сборки тоже его
содержат. Вручную:

```bash
cd frontends/tui/glass && cargo build --release   # лаунчер найдёт target/release/kvist-glass
kvist --frontend glass                              # или /tui glass, сохраняется на следующие запуски
```

Лаунчер ищет `KVIST_GLASS`, затем `kvist-glass` в PATH, затем сборку этой
рабочей копии, и передаёт своё ядро в `KVIST_CORE_CMD`. При прямом запуске
`kvist-glass --workspace /путь/к/проекту` берётся ядро рабочей копии.

- Ядро берётся из `KVIST_CORE_CMD` (JSON-массив строк, как его передаёт
  лаунчер Ink-приложению), иначе из этой рабочей копии:
  `.venv/bin/python kernel/__main__.py`. Его stderr пишется в
  `kvist-glass-core-<pid>.log` во временной папке; журнал удаляется, если ядро
  завершилось чисто, и остаётся в остальных случаях.
- Одноразовые операции с сессиями (запуск, история сессии, история ввода,
  прощание) выполняются в `KVIST_SESSION_CMD`, когда лаунчер его задаёт: это
  нативная программа сессий, только для ядра на этой машине
  (`docs/UI_API.ru.md`, §8a). Без неё они идут в ядро.
- Фотография показывается одна, пока ядро не пришлёт `hello` (около 10–15 с,
  в основном ядро загружает списки моделей). Если ядро не запустилось, там же
  видна причина и путь к журналу.
- Смену провайдера и моделей ядро сохраняет, как и везде. Чтобы попробовать,
  не трогая свои настройки, укажи в `KVIST_CONFIG_DIR` копию `~/.kvist`.
- `KVIST_GLASS_FPS` задаёт частоту кадров, пока что-то движется (по умолчанию
  60, от 20 до 240; другое значение останавливает запуск с объяснением). Ставь
  частоту своего монитора: kitty показывает не чаще неё (`sync_to_monitor`) и
  не больше 100 кадров при своём `repaint_delay 10` по умолчанию. Анимации
  отмеряются в миллисекундах, поэтому частота меняет плавность, но не
  скорость. Когда ничего не движется, экран перерисовывается с частотой видео, 24 кадра/с, а
  ввод рисуется сразу.
- Встроенный `assets/backdrop-night-forest.mp4` проигрывается по кругу без звука;
  конец исходника плавно смешан с началом за две секунды (цикл около 8 с).
  Нужен ffmpeg: сначала `KVIST_FFMPEG`, затем PATH, затем
  `~/.local/share/kvist/ffmpeg/ffmpeg` из установщика релизов. Если декодер
  недоступен, остаётся неподвижный фон и появляется сообщение с причиной.
  Ролик включён в Rust-бинарник.
- Язык берётся из `KVIST_LANG`, затем из `LC_ALL` / `LANG` (`ru` или английский).

## Клавиши и мышь

Главные действия на клавиатуре; панели, превью и списки выбора открываются и
мышью.

| Клавиша | Мышь | Что делает |
|---|---|---|
| Enter | | отправить (Shift+Enter или Alt+Enter: новая строка) |
| ↑ / ↓ | | сдвинуть курсор на строку с сохранением колонки; на первой или последней строке — в начало или конец текста, а дальше ↑ листает прежние вводы (рабочей папки, их хранит ядро), ↓ возвращает вперёд к черновику |
| Alt или Ctrl + ← / → | | курсор на слово назад или вперёд (Alt+b / Alt+f делают то же) |
| Alt или Ctrl + Backspace / Delete | | удалить слово перед курсором или после него |
| `/` | | открыть список команд; набор сужает его до имён, которые начинаются с введённого |
| ↑ / ↓ в списке | наведение | выбрать команду (по кругу) |
| Tab в списке | | дополнить выбранное имя (`/style `) и вводить аргументы |
| Enter в списке | клик по строке | выполнить выбранную команду, а не набранное начало; `/rename` только дополняется, ему нужно имя |
| `/имя аргументы` + Enter | | команда ядра (`/provider`, `/models`, `/role`, `/effort`, `/new`…) |
| Ctrl+P | клик по модели в строке состояния | выбрать модель любого подключённого провайдера |
| | клик по провайдеру в строке состояния | выбрать провайдера (`/provider`) |
| `/tui` + Enter | | выбрать терминальный интерфейс; лаунчер запустит его сейчас и в следующие разы |
| Esc, Esc | | остановить идущий ход (после первого Esc видно, что сделает второй) |
| | клик по превью браузера | открыть браузер в центре; Esc закрывает |
| | `O` в открытом браузере | открыть превью в вашем браузере |
| Ctrl+T | клик по «Помощницы» или по помощнице | открыть панель помощниц; Esc закрывает |
| PageUp / PageDown | колесо | прокрутить разговор |
| | нажать и вести по разговору | налить воду на текст: выделение течёт за указателем, а при отпускании кнопки текст копируется |
| | двойной / тройной клик | облить слово / строку и скопировать |
| Esc | клик в другом месте | дать воде стечь (пока на стекле вода, Esc сначала убирает её) |
| Ctrl+C | | выйти |

Выделение текста — это вода, которую наливают на стекло. Левая кнопка роняет
каплю туда, где нажата; движение с зажатой кнопкой льёт воду, и она бежит по
тексту вслед за указателем (от быстрого отстаёт и догоняет), а потом оседает
лужей с круглой кромкой, которая ловит свет. Лужа — полупрозрачная картинка над
фоном ячеек и под текстом (z-index kitty), поэтому буквы остаются чёткими, а
под водой они светлеют. При отпускании текст уходит в буфер обмена через
терминал (OSC 52; значки и полоска цитаты не копируются), в строке состояния
появляется «Скопировано». Если держать указатель выше или ниже разговора, он
прокручивается. Shift+перетаскивание по-прежнему отдаёт выделение самому
терминалу.

Ответы агента рисуются как Markdown (pulldown-cmark): заголовки, вложенные
списки, цитаты, линии, ссылки с адресом, чек-листы, таблицы и блоки кода с
подсветкой синтаксиса (syntect с грамматиками two-face: TypeScript, TOML,
GLSL и другие). Одиночный перенос строки в ответе остаётся переносом. Курсор
ввода — собственная мигающая черта терминала цвета лунного света (OSC 12).

Ctrl+P показывает модели всех подключённых провайдеров (команда ядра
`catalog`: сохранён ключ или вход, живой список моделей) под именем
провайдера, текущий отмечен. Tab переключает, какую модель выбираешь: умную
или быструю; печатай для фильтра. Модель другого провайдера переключает и
провайдера, а вторая роль берёт модель, которая у этого провайдера уже
выбрана (`models PROVIDER FAST SMART`, одна пересборка).

Любой вопрос ядра (выбор, текст, ключ, подтверждение) открывает один и тот же
стеклянный диалог: печатай, чтобы отфильтровать список, стрелки и Enter для
ответа, Esc для отмены. Одобрение команды показывает саму команду и оценку
риска от ядра; ответы «Да», «Всегда» (только когда ядро предлагает запомнить
шаблон) и «Нет», заранее выбрано «Нет». Одобрение перезаписи файла показывает
изменение в широком диалоге: слева старый файл, справа новый, номера строк
обоих файлов, цвета синтаксиса, удалённые и добавленные строки подкрашены, а
изменившаяся часть переписанной строки выделена. Колесо или стрелки вверх и
вниз листают дифф; влево и вправо выбирают ответ. Закрытая сессия заменяет поле ввода
текстом ядра и одной кнопкой «Новая сессия» (`/new`); Enter делает то же.

Щелчок по файлу в карточке «Изменено» открывает справа панель с тем, что агент
сделал с этим файлом (в окнах от 124 колонок): все правки сессии по порядку,
строки пронумерованы, с цветами синтаксиса, удалённые и добавленные строки
подкрашены, изменившаяся часть переписанной строки выделена. Колесо над панелью
листает; повторный щелчок по файлу, крестик или Esc закрывают её. Пока панель
открыта, она занимает место карточек браузера и помощниц. Дифф ядро присылает
вместе с каждой записью, поэтому для файла, изменённого в сессии, сохранённой
до этого, видны только счётчики.

## Команды этого интерфейса

В списке по `/` те же команды, что в Ink. Большинство уходит в ядро (в том числе
`/export`, `/resume`, `/feedback`, `/gmail`, `/telegram`). `/website` отправляется
обычным запросом, который ядро раскрывает само. Четыре команды обрабатываются
здесь и до ядра не доходят: `/help` (список команд прямо в разговоре), `/copy [N]`
(последний ответ или N-й с конца в буфер обмена), `/clear` (разговор на экране
начинается заново; пока идёт ход, не работает) и `/quit` (также `/exit` и `/bye`).
`/resume` — ход без собственного запроса: Esc Esc его останавливает, а
заканчивается он одним `turn_end`.

## Мысли модели

Если провайдер передаёт мысли (события `reasoning_*`, `docs/UI_API.ru.md`, §7),
они показываются над ответом: заголовок «Думаю» с секундами, а под ним последние
пять строк мысли на тонкой линии, к верху тусклее. Когда модель заканчивает
думать, окно сворачивается в одну строку «Думал N с». Если провайдер не присылает
текст мыслей, остаётся только строка «Думаю», как раньше.

Текст не придерживается ради красоты: несколько символов рисуются в ту же секунду,
как пришли. Пакет (некоторые провайдеры шлют мысль крупными кусками) догоняется
примерно за секунду, каким бы большим он ни был, так что текст течёт, а не
прыгает. В журнале помощницы или исполнителя мыслей нет.

## Вызовы модели

Вызовы, идущие подряд без слов, мысли и ошибки между ними, — одна группа (`batch_id` ядра не используется: он делит записи и команды одного ответа на разные пачки). Пока модель
работает, группа открыта: каждый вызов — строка с иконкой и описанием. Когда
начинается следующий запрос модели (она начала думать, отвечает или снова
вызывает), группа остаётся на виду две секунды и затем с анимацией сворачивается
в одну строку: «▸ Вызовов: 4 · ошибок: 1». Клик по ней раскрывает группу обратно.
Клик по вызову раскрывает то, что отправила модель (**Ввод**: команда `run_shell`,
у остальных аргументы), и то, что вернулось (**Вывод**, при ошибке красный);
длинное обрезается до нескольких строк с пометкой «… ещё N». Что человек открыл
или свернул вручную, остаётся как он оставил. У ответа с одним вызовом строки
группы нет, но вызов раскрывается так же.

## best-of и council

`/best-of N <задача>` и `/council <вопрос>` — команды ядра, но это целые ходы:
ядро присылает события хода, потом `turn_end`, потом `command_result`. Пока ход
идёт, Esc Esc останавливает его, как обычно; после конца поле ввода снова
свободно. Обе команды есть в списке по `/` (Enter дописывает имя, дальше —
аргументы).

**Арена best-of** занимает место разговора, пока идёт прогон. Заголовок
«best-of» и строка о том, что это такое; ниже по две строки на исполнителя:
стиль, состояние, шаг, тесты (значок и краткая сводка), размер правок
(`+добавлено −удалено · файлов`), деньги или токены; и ветка с его последним
вызовом. Выбывший исполнитель приглушён, под ним причина. Строка выбирается
стрелками ↑/↓ (пока поле ввода пусто) или наводится мышью; Enter или щелчок
открывают **журнал исполнителя только для чтения**: его сессию, шаги и
результаты (то же `--session-op history`, что у `/session`). В журнале Esc —
назад, ↑/↓ и PgUp/PgDn листают, Ctrl+R читает журнал заново (исполнитель мог
уйти вперёд). Когда прогон закончился, под таблицей стоит итоговая строка, а
Esc убирает арену и возвращает разговор.

**Экран решения** — вопрос ядра с `purpose: "bestof_decision"`: таблица
вердикта (стиль, итог, тесты, правки, заметка), победитель и причина, четыре
действия: «Принять» (`accept`, всегда победитель), «Посмотреть diff» (`diff:<id>`
строки, на которой стоишь), «Выбрать другого» (`pick:<id>` строки; на строке
победителя — `other`, и ядро спросит само) и «Выбросить всё» (`discard`). ↑/↓
выбирают строку, ←/→ — действие, Enter выполняет, буквы `a`, `d`, `p`, `x` (и
`ф`, `в`, `з`, `ч`) — сразу; Esc — «пока не решаю». Пришёл `bestof_diff` — патч
показан по файлам тем же видом, что и диф в панели; Tab переключает таблицу и
патч, колесо и ↑/↓ листают. Без вердикта или для чужого прогона вопрос
остаётся обычным списком.

**Council**: четыре карточки (угол и строка о нём: простота, безопасность,
скорость разработки, цена поддержки) наполняются по мере прихода `council_card`; под
карточкой — риски из `council_objection` с адресатом. После `council_verdict`
выбранная карточка выделена, ниже причина и несогласные с доводами. Esc
убирает экран.

**Строка статуса** справа: способ вызовов (`native` / `text`, из `tool_mode`),
заполненность контекстного окна («контекст 27,3 тыс. / 400,0 тыс. · 85% в кэше»:
`context_tokens` и `context_limit` последнего `usage`, `cache_read_tokens` как доля его
`input_tokens`; доли нет, если провайдер не сообщил про кэш) и деньги: сумма `cost_usd`
основного потока и последних снимков исполнителей; «≈», если цена где-то приблизительна
или у какого-то вызова её нет. Суммарный расход токенами не показывается: он выглядит как
разговор, которого нет. Наведение на контекстное окно показывает, сколько ещё проживёт
кэш. Ни один провайдер этого не сообщает, поэтому счёт идёт пять минут от конца
последнего вызова (обычный срок) и подписан «скорее всего»; если провайдер хранит кэш
дольше (24 ч у OpenAI), цифра занижена. Без `context_tokens` в `usage` (старое ядро)
строка возвращается к «всего N ток · M некэш.». Числа берутся только из событий.

## Как это рисуется

- `video.rs` декодирует ролик по кругу в RGB 960×540, 24 кадра/с, в отдельном
  потоке, сохраняя только последний кадр. При выходе декодер останавливается.
- `backdrop.rs` подгоняет кадр под окно и в фоновом потоке готовит четыре
  его размытые и более тёмные версии. Текстуры ограничены 960×540, размытые
  ещё меньше; kitty масштабирует их под окно. В очереди не больше одного готового кадра.
- Каждая карточка — отдельная картинка: вырезка размытого кадра под ней,
  тонированная, со сглаженными скруглёнными углами и тонким бликом по краю.
  Карточки ездят перемещением размещения с пиксельным смещением, поэтому
  движение плавнее одной ячейки.
- Для каждого кадра загружаются только видимый уровень размытия и карточки
  (файлами в `/dev/shm`, если поддерживается, иначе сжатыми прямо в поток).
  Старые картинки освобождаются после размещения новых.
- Превью браузера — событие ядра `screen`: `screen.rs` читает его
  `stream_url` (MJPEG-поток, только локальный адрес; 30 кадров в секунду, ядро
  меняет это через `KVIST_SCREEN_FPS`). Открытый браузер показывает каждый кадр;
  маленькая карточка пересобирает картинку не чаще чем раз в 120 мс, а размытые
  ступени открытия делаются только при открытии.
- Движения идут по кривой «рывок» (`anim.rs`): медленный старт, короткая
  быстрая середина и долгое мягкое торможение (на 600 мс примерно 200, 50 и
  350 мс). Открытие браузера и появление превью вместо этого слегка
  перелетают цель.
- Текст — обычные ячейки поверх картинок. Картинки лежат под ячейками с цветом
  фона, поэтому подсвеченная строка закрывает стекло.
- Собственный отступ терминала закрашивается цветом краёв фотографии (OSC 11)
  и возвращается при выходе (OSC 111).
- Блочная формула (`\[ … \]`, `$$ … $$`) верстается RaTeX (`math.rs`) и
  рисуется картинкой поверх строк, которые для неё резервирует лента: по
  центру колонки, при прокрутке обрезается вместе с текстом. Формулы внутри
  строки и те, что RaTeX не разобрал, показываются текстом (`√9 ≈ 3`).
  Вёрстка формул: RaTeX (MIT) со шрифтами KaTeX (SIL OFL 1.1), см.
  [THIRD_PARTY.md](THIRD_PARTY.md).

## Что приходит из ядра

- Добавленные и удалённые строки по файлам берутся из `action_result`
  (`lines_added`, `lines_removed`): это построчный дифф самого исполнителя.
  Поле `patch` того же события — унифицированный дифф записи, а
  `subject.diff` одобрения перезаписи — ещё один; оба читает `diff.rs`.
- Панель помощниц показывает вызовы каждой помощницы по ходу работы с концом
  их вывода (`helper_activity`); левая карточка показывает, чем помощница
  занята сейчас.
- После `/session` лента заполняется заново из журнала сессии
  (`--session-op history`, последние 500 событий). Вызовы и помощницы, которые
  журнал не довёл до конца, показаны остановленными, а если более ранние события
  не поместились, всплывает уведомление.
