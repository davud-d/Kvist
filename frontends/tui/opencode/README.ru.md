# Терминал OpenCode для Kvist

Терминальный интерфейс [OpenCode](https://github.com/anomalyco/opencode) (TypeScript,
[OpenTUI](https://github.com/anomalyco/opentui) + SolidJS), который рисует сессию Kvist. Здесь
только интерфейс: сервера, сессий, провайдеров, инструментов и агентного цикла OpenCode нет. Где
в OpenCode есть то, чего нет в Kvist, интерфейс показывает то, что есть в Kvist.

```bash
(cd frontends/tui/opencode && bun install)             # один раз; нужен Bun 1.3.14 или новее
.venv/bin/python -m kernel --frontend opencode          # или /tui, затем «OpenCode terminal»
```

Сборки нет: Bun запускает TypeScript из исходников. Без Bun, без `bun install` или без терминала
Kvist запустит интерфейс Ink и скажет почему. В релизные бинарники этот интерфейс пока не входит:
он работает из исходников.

## Как выглядит

Главный экран: слово Kvist, поле ввода в рамке с цветной полосой и подсказка. Слово — то же, что Kvist печатает при выходе (из интерфейса Ink), в двух синих; совсем маленькое окно получает малый знак OpenCode. Сессия — лента:
запрос в приподнятом блоке с полосой, слова модели markdown'ом, чтение и поиск — по одной
приглушённой строке (`→ Read a.py`, `✱ Grep "main"`), запись и правка — блоки с номерами строк и
диффом, команда с выводом (десять строк, клик раскрывает остальное), свёрнутая строка
`Thought · 3s` и `Coder · fast-model · 12s` в конце хода. Рядом с лентой, от 120 колонок, —
боковая панель: заголовок сессии, расход контекста, фоновые задачи и изменённые файлы.

Сессия, которую ядро закрыло (после оскорблений), ставит на место поля ввода сообщение ядра и кнопку «Новая сессия», как в Glass; `Enter` или клик открывает новую сессию. Пока идёт ход, строка со спиннером показывает, что по словам ядра оно сейчас делает, пока не пойдут слова.

Подтверждения занимают место поля ввода: `Allow once`, `Allow always` (для опасной команды его
нет) и `Reject`; над ними команда или дифф перезаписи.

## Клавиши

Это клавиши OpenCode по умолчанию (`<leader>` — это `Ctrl+X`).

| Клавиша | Действие |
|---|---|
| `Enter` / `Shift+Enter` | отправить / новая строка |
| `Shift+Tab` | следующая роль (агенты OpenCode); `<leader>` `a` — список |
| `Ctrl+T` | следующий уровень рассуждений (варианты модели OpenCode) |
| `Ctrl+P` | список команд |
| `<leader>`, затем `n` `l` `m` `a` `t` `b` `s` `u` `y` `h` `q` | новая сессия, сессии, модели, роли, темы, боковая панель, статус, отмена изменений, копировать последний ответ, справка, выход |
| `Ctrl+R` | переименовать сессию |
| `Esc` дважды | поставить запуск на паузу, состояние сохраняется |
| `Ctrl+C` | очистить ввод; при пустом вводе и идущем запуске — остановить всё; дважды в покое — выйти |
| `PgUp` / `PgDn` | прокрутка ленты |
| `Up` / `Down` | между строками текста; на краю — сначала к началу или концу, затем по прежним запросам. Под пустым полем при первом запуске выбирают один из трёх предложенных запросов (`Tab` или `Enter` вписывает его в поле) |
| `/` | слэш-команды; `Tab` дополняет, `Enter` выполняет |
| `@` | файл проекта; `Tab` или `Enter` вписывает его путь в запрос |

Текст, выделенный мышью, копируется при отпускании кнопки.

## Что есть в OpenCode и чем заменено

| OpenCode | Здесь |
|---|---|
| агенты (build, plan) | роли Kvist: auto, coder, reader, devops, chat, universal |
| модель и её варианты | быстрая и умная модель; уровень рассуждений |
| подключение провайдера | `/provider`, `/change-api`, `/settings-api` (диалоги ядра, нарисованные как диалоги OpenCode) |
| сессии, форк, undo | `/session`, `/new`, `/revert`, `/changes` |
| `/export` ленты | `/export` ввозит сессии других агентов (Claude Code, Codex, OpenCode, Cursor …) |
| список дел, MCP-серверы | фоновые задачи; скиллы ядра |
| запрос разрешения | подтверждения ядра |
| темы | собственная система тем OpenCode и его 33 темы; `theme.json` ядра тоже работают |

Нет, потому что в Kvist за ними ничего нет: публикация сессии, компактификация, рабочие области и
worktree, терминальные панели, плагины, аккаунт OpenCode и его каталог моделей.

## Темы

Система тем OpenCode используется как есть: его 33 темы, светлый и тёмный режим, `/themes` с
предпросмотром на лету. Файл темы ищется в таком порядке, от низшего приоритета: `kernel/themes/`
ядра, `~/.config/opencode/themes/`, `~/.kvist/themes/` (или `$KVIST_CONFIG_DIR/themes/`),
`<workspace>/.kvist/themes/`. Темы в 50-слотовом формате `theme.json` ядра при загрузке
преобразуются; тема, где слотов не хватает, берёт их из поставляемой темы `kvist`. Выбор темы,
светлый/тёмный режим, переключатели боковой панели и размышлений хранятся в
`~/.kvist/opencode-tui.json` — файле этого интерфейса; `config.json` ядра не трогается.

## Откуда код

Всё в `src/oc/` — **скопированный исходник OpenCode** (MIT, см. `THIRD_PARTY.md`) с теми же
относительными путями, урезанный до того, что есть в Kvist: без сервера, SDK, плагинов, рабочих
областей и синхронизации. Поэтому интерфейс выглядит и ведёт себя как OpenCode: система тем,
клавиши, диалоги, тосты, спиннер, дифф, компоненты логотипа и части сообщений ленты. Остальное —
клей Kvist.

```text
src/main.ts        точка входа лаунчера (подключает плагин Solid для Bun, затем cli.tsx)
src/cli.tsx        аргументы, рендерер, прощание
src/app.tsx        стек провайдеров OpenCode, глобальные клавиши, вопросы ядра как диалоги
src/kvist.tsx      единственное место, которое говорит с ядром: процесс, события, команды
src/commands.tsx   список команд (палитра, слэш) под идентификаторами команд OpenCode
src/tools.ts       как описывается действие и какой блок оно получает   src/files.ts  что предлагает «@»
src/screens/       главный экран, сессия, ввод, лента, боковая панель, подтверждения, палитра, диалоги
src/oc/            файлы самого OpenCode (tui/, theme/, типы plugin/), см. выше
tests/             bun test: чистые модули и всё приложение на скриптовом ядре из набора Ink
```

Ядро подключается по `--frontend stdio-multi --wake`, как у интерфейса Ink; редьюсер событий,
адаптер процесса и операции с сессиями — это модули приложения Ink
(`frontends/tui/ink/{state,core,session,format,diff,approval,commands}.ts`), импортируемые оттуда.
Изменение в них проверяется с обеих сторон.

## Разработка

```bash
cd frontends/tui/opencode
bun install
bun run typecheck
bun test                     # тесты приложения запускают frontends/tui/ink/tests/fixtures/fake-core.mjs на Node
SHOW_FRAMES=1 bun test       # печатает каждый кадр, на который смотрит тест
bun run start -- --workspace /путь/к/проекту
```

OpenTUI нужен Bun 1.3.14+ (или Node 26.4+, на него этот интерфейс не рассчитан). Тесты видят
символы, а не цвета: вид проверяйте в настоящем терминале.
