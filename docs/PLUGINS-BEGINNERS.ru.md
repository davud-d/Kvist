# Свой плагин для Kvist за 5 минут (для тех, кто никогда не писал код)

English version: [PLUGINS-BEGINNERS.md](PLUGINS-BEGINNERS.md). Подробное описание: [PLUGINS.ru.md](PLUGINS.ru.md).

## Что такое плагин

Плагин — это твоя собственная команда для Kvist. Например, ты пишешь `/simple`, и Kvist начинает объяснять
всё очень простыми словами. Или пишешь `/novibecode`, и Kvist перестаёт писать код за тебя и начинает учить.

Плагин — это папка с одним маленьким текстовым файлом. Ничего устанавливать не нужно.

Пока плагины запускаются только на Linux.

## Шаг 1. Найди папку

Открой папку своего проекта, ту, в которой ты запускаешь Kvist. Создай в ней папку с именем `plugins`.

```
мой-проект/
  plugins/      ← вот эта
```

Хочешь, чтобы команда работала во всех проектах сразу? Тогда создай папку `plugins` здесь:

* Linux и macOS: `~/.kvist/plugins/` (`~` — это твоя домашняя папка)
* Windows: `C:\Users\ТвоёИмя\.kvist\plugins\`

## Шаг 2. Создай папку для своей команды и файл в ней

Внутри `plugins` создай папку `simple`. Имя папки может быть любым, лишь бы ты сам понимал, что в ней.

В папке `simple` создай файл с именем ровно `plugin.py`. Подойдёт любой текстовый редактор: VS Code, Блокнот,
что угодно. Главное, чтобы файл назывался именно `plugin.py`, а не `plugin.py.txt` и не `simple.py`.

```
мой-проект/
  plugins/
    simple/
      plugin.py     ← сюда пишем
```

Каждая команда живёт в своей папке. Захочешь вторую команду — сделай рядом вторую папку.

## Шаг 3. Скопируй туда это

```python
"""Объясняй как пятилетнему."""


def command():
    return "simple"


def run(request):
    return "Объясняй очень простыми словами, без терминов, с примером из жизни."
```

Сохрани файл.

Что здесь что:

| Строка | Что значит | Что можно менять |
| --- | --- | --- |
| `"""Объясняй как пятилетнему."""` | подпись команды в меню | любой текст |
| `return "simple"` | имя команды: `/simple` | маленькие латинские буквы, цифры и `-` |
| `return "Объясняй ..."` | что Kvist должен делать | любой текст, это и есть твоя инструкция |

Остальное (`def`, `run(request)`, двоеточия, отступы) оставь как есть. Отступ — это 4 пробела в начале строки,
не удаляй их.

## Шаг 4. Перезапусти Kvist

Закрой Kvist и открой снова. Меню команд собирается при запуске.

## Шаг 5. Попробуй

Набери `/si`: в списке появится `/simple`. Допиши вопрос и нажми Enter:

```
/simple что такое API?
```

В первый раз Kvist спросит: «Запустить плагин /simple?». Согласись. Это защита: Kvist не запускает чужие файлы
без спроса. Больше он не спросит, пока ты не изменишь файл.

Готово, у тебя есть свой плагин.

## Длинная инструкция в отдельном файле

Если инструкция большая, неудобно писать её в кавычках. Положи её в ту же папку, в обычный текстовый файл.

```
plugins/
  novibecode/
    plugin.py
    novibecode.md
```

`plugins/novibecode/novibecode.md`:

```markdown
Помогай человеку писать код самому. Не пиши код за него, даже кусочек.
Объясни подход простыми словами, задай один наводящий вопрос
и скажи, какую страницу документации почитать.
```

`plugins/novibecode/plugin.py`:

```python
"""Учи, а не пиши код за меня."""
import kvist


def command():
    return "novibecode"


def run(request):
    return kvist.read("novibecode.md")
```

`kvist.read("novibecode.md")` значит «возьми текст из файла novibecode.md в этой же папке».

Инструкцию в `.md` можно менять сколько угодно: Kvist не будет каждый раз спрашивать разрешения, потому что это
просто текст, а не код.

## Чуть умнее: команда, которая смотрит, что ты написал

Это файл `plugins/review/plugin.py`. `request` — это то, что ты набрал после команды. Если ты написал `/review main.py`, то `request` равен
`"main.py"`. Если только `/review`, то `request` пустой.

```python
"""Проверь мой код и найди ошибки."""
import datetime


def command():
    return "review"


def run(request):
    if request == "":
        return "Спроси у человека, какой файл проверить."
    today = datetime.date.today().strftime("%d.%m.%Y")
    return "Сегодня " + today + ". Проверь файл " + request + " и найди ошибки. Сам ничего не исправляй."
```

Если `request` пустой, Kvist спросит, какой файл проверить. Если нет, получит инструкцию с сегодняшней датой и
именем файла.

## Подсказки в редакторе

Если в VS Code или JetBrains стоит плагин Kvist, то в файле из папки `plugins` он подсказывает код именно для
плагинов. Начни печатать, и он предложит, что писать дальше.

## Что-то не работает

| Что видишь | Что делать |
| --- | --- |
| Команды нет в меню | Перезапусти Kvist. Проверь, что файл лежит в `plugins/твоя-папка/` и называется ровно `plugin.py`, а не `plugin.py.txt` |
| `Plugin skipped: ... a plugin lives in its own folder` | Файл лежит прямо в `plugins`. Сделай для него папку и переименуй в `plugin.py`, как написано в сообщении |
| `... must be named plugin.py` | Файл в папке назван по-другому, например `simple.py`. Переименуй его в `plugin.py` |
| `Plugin skipped: ... must only return the name as plain text` | В `command()` имя должно быть в кавычках: `return "simple"` |
| `... use lowercase letters` | Имя только из маленьких латинских букв, цифр и `-`: `my-helper`, а не `My Helper` |
| `... is a built-in Kvist command` | Такое имя уже занято самим Kvist (например, `new` или `help`). Придумай другое |
| `... syntax error on line 5` | Опечатка в строке 5. Чаще всего это забытая кавычка, двоеточие или пропавший отступ |
| `... no command()` или `no run(request)` | Удалилась одна из двух функций. Скопируй пример ещё раз |
| `/simple failed: ...` | Ошибка внутри `run`. Последняя строка сообщения говорит, что не так |
| `... cannot run here` | Плагины пока запускаются только на Linux, на других системах их нельзя запустить |

## Можно ли сломать компьютер плагином

Нет. Плагин работает в закрытой «коробке»: он видит только свою собственную папку и не имеет доступа к другим
плагинам, интернету, твоим файлам и паролям. Так что даже плагин из чужого проекта ничего плохого не сделает. А перед первым
запуском Kvist всё равно спросит тебя.
