# Плагины Kvist: своя слэш-команда в одном файле

English version: [PLUGINS.md](PLUGINS.md). Никогда не писал код? Начни с пошаговой
[инструкции для новичков](PLUGINS-BEGINNERS.ru.md).

Плагин — это одна папка, в которой лежит `plugin.py`. Положил папку в `plugins`, и в Kvist появилась новая команда. Манифест и
сборка не нужны, знать, как Kvist устроен внутри, тоже не нужно. Для расширений побольше (инструменты для
модели, сеть, экран) есть [скиллы](SKILLS.ru.md).

## Куда класть папку

```
plugins/
  novibecode/
    plugin.py        сама команда (обязателен, именно с таким именем)
    novibecode.md    её инструкции (любые файлы, какие хочешь)
    helpers.py       твой модуль, если нужен: import helpers
  review/
    plugin.py
```

| Папка `plugins` | Где работают команды |
| --- | --- |
| `plugins/` в твоём проекте | только в этом проекте |
| `~/.kvist/plugins/` | во всех проектах |

Если в обеих есть команда с одним именем, побеждает та, что в проекте. Каждый плагин видит только свою папку,
так что два плагина не могут читать файлы друг друга.

## Весь API: две функции

```python
# plugins/novibecode/plugin.py
"""Teach instead of writing the code."""
import kvist


def command():
    return "novibecode"


def run(request):
    return kvist.read("novibecode.md") + "\n\nThe person asks: " + request
```

```markdown
<!-- plugins/novibecode/novibecode.md -->
Помогай человеку писать код руками. Не пиши его за него: подсказывай,
объясняй подход, задавай наводящие вопросы, отправляй в документацию.
```

* `command()` возвращает имя команды: `/novibecode`. Это должен быть просто текст в кавычках (строчные буквы,
  цифры, `-`), потому что Kvist читает его, не запуская твой файл.
* `run(request)` получает то, что ты написал после команды (`/novibecode циклы` даёт `"циклы"`, голая
  `/novibecode` даёт `""`), и возвращает текст. Этот текст уходит модели Kvist как инструкция для этого запроса.
* Первая строка docstring файла — описание команды в меню `/`.
* `import kvist` по желанию. В модуле одна функция: `kvist.read("file.md")` возвращает текст файла из папки
  плагина (`kvist.read("prompts/short.md")` тоже работает).
* Другие `.py` в папке — твои собственные модули: `import helpers` в `plugin.py` найдёт `helpers.py`.

В `run` может быть любая логика: выбрать инструкцию по запросу, добавить сегодняшнюю дату, склеить несколько
файлов. Kvist прочитает то, что функция вернёт.

## Безопасность

* Перед первым запуском плагина Kvist спрашивает: «Запустить плагин /novibecode?» и показывает папку, её
  Python-файлы и один SHA-256 на все. Ответ запоминается для этого кода в этом проекте. Изменился `.py` в папке
  или появился новый — Kvist спросит снова. Правка инструкций в `.md` вопроса не вызывает.
* `run` выполняется в песочнице. Он видит копию своей папки, снятую в момент одобрения, и стандартную библиотеку
  Python, больше ничего: ни других плагинов, ни сети, ни файлов проекта, ни домашней папки, ни ключей, ни
  переменных окружения. Плагин, пришедший вместе с чужим
  репозиторием, ничего не сделает только тем, что лежит в папке.
* На `run` даётся 30 секунд. `print` внутри уходит в лог и ничего не ломает.
* Для запуска нужна песочница Linux (Bubblewrap и системный `/usr/bin/python3`). На других системах Kvist
  показывает команду, но объясняет, почему не может её запустить.

## Если что-то не так

Плагин без годной команды (нет `command()` или `run`, имя не простым текстом, встроенное имя вроде `/new`,
синтаксическая ошибка) пропускается, и терминал одной строкой пишет почему. Так же пропускаются `.py`,
лежащий прямо в `plugins/`, и папка, где Python-файл назван не `plugin.py`: в строке написано, куда его
перенести или как переименовать. Ошибка внутри `run` показывается
вместо ответа, с последними строками трассировки.

## Автодополнение

Когда ты правишь Python-файл в папке плагина (`plugins/<имя>/`) или файл с `import kvist`, инлайн-подсказки Kvist в IDE знают этот API.
Они предлагают `return "имя"` в `command()` и `kvist.read(...)` в `run` и не придумывают функций, которых нет.

## Интерфейсы

Команды плагинов видны в меню `/` терминалов Ink и Claude-style, в OpenCode и в Classic (Glass). В Classic
Legacy их просто набирают. Команду разворачивает ядро, так что её запустит любой интерфейс, который отправляет
набранную строку как запрос.
