# Kvist на сервере

Kvist может работать на другой машине и продолжать, пока вас нет: закрыли интерфейс, выключили компьютер,
вернулись завтра, подключились — и видите, что агент сделал за это время. Агент живёт на сервере службой,
ваш интерфейс достаёт до него по ssh.

```
интерфейс ── ssh ──> сервер: демон Kvist (служба) ── пишет каждое событие в файл журнала
 (любой компьютер)           └─ агент работает, подключён к нему кто-нибудь или нет
```

## Что нужно

- Сервер на Linux, macOS или BSD, на нём установленный Kvist (`~/.local/share/kvist/kvist-core`, туда его ставит
  установщик) и настроенный провайдер (один раз `ssh -t HOST kvist-core --setup`).
- Вход по ключу (ssh-agent или ключ без пароля). Пароль ввести нельзя: соединение открывается без терминала, и
  Kvist никогда не отвечает на вопросы ssh. В первый раз выполните `ssh HOST` сами, чтобы принять ключ хоста.
- На вашем компьютере для интерфейса нужен только `ssh`. Сервером Windows быть не может.

## Запуск

```
kvist --remote me@server --remote-workspace /home/me/project
```

Сначала Kvist спрашивает сервер: есть ли там Kvist, та ли версия, настоящая ли папка, настроен ли провайдер.
Если для этой папки агент не запущен, он предложит **установить службу** (рекомендуется: она поднимается после
перезагрузки и после падения), запустить один раз или отменить. Потом интерфейс открывается как обычно.
`--frontend` выбирает какой (`tui`, `claude`, `opencode`, `glass`, `voice`). В интерфейсах на Ink то же самое
делает команда `/remote user@host /папка` изнутри, а `/remote off` возвращает на эту машину.

`user@host:2222` задаёт порт. Имена из `~/.ssh/config` работают.

## Что происходит, когда вы уходите

Агент продолжает работу. Закрыли интерфейс, опустили крышку, пропала сеть — демону на сервере всё равно. Вопрос,
на который нужен ответ (подтверждение, план), ждёт вас. Запланированные пробуждения и завершившиеся фоновые
команды запускают свои ходы сами.

Когда вы подключаетесь снова, интерфейс перерисовывается из журнала событий демона: законченные ходы такими, какими
они закончились, ход в процессе — как он есть, диалоги, которые ещё открыты. Обрыв посреди сеанса (плохая связь,
перезагрузка сервера) обрабатывает прокси, который работает у вас: он переподключается с паузами 1, 2, 4 … 30 секунд
и продолжает ровно с того места, где остановился, ничего не повторяя. Он сдаётся через 10 минут или сразу, когда
ожидание не поможет (неизвестен ключ хоста, ssh отказал во входе, Kvist не установлен, служба не запущена), и
говорит почему. Бесконечно стучаться в Kvist, которого там нет, он не будет.

## Пишет только один

Одну сессию могут смотреть несколько интерфейсов, но **ведёт** её один. Кто подключился первым — ведёт; любой другой
показывает баннер на месте строки ввода: *«сессией управляет другой фронтенд · Enter — перехватить управление»*.
Сервер отбрасывает всё, что присылает наблюдатель, поэтому два интерфейса никогда не положат две задачи в одну
сессию. Enter на баннере перехватывает управление; прежний водитель сразу становится наблюдателем. Диалоги, которые
ещё ждут, отправляются тому, кто перехватил.

Если у водителя пропало питание, роль освобождается сама через 20 секунд без признаков жизни, и её получает
следующий интерфейс, который попросит.

## Служба

| Система | Что устанавливается | Когда стартует |
|---|---|---|
| Linux с systemd | пользовательский unit `kvist-<id>.service` (`Restart=on-failure`) | при загрузке, если включён linger (`loginctl enable-linger`: Kvist пробует сам, иначе сообщает команду для `sudo`), иначе при входе |
| macOS | LaunchAgent `site.kvist.remote.<id>` | когда вы входите в Mac, а не при загрузке |
| BSD, Linux без systemd | строка `@reboot` в вашем crontab | при загрузке; **после падения не перезапускается** |

Управляют ими `kvist --remote-op install-service|uninstall-service|start|stop|status|probe --remote HOST
--remote-workspace PATH`. `start` запускает демон один раз, без службы. Один демон обслуживает одну папку.

После перезагрузки или падения демон стартует с чистым журналом и пишет об этом в ленту. Задача, которая шла, сама
не продолжается (ни одна правка не повторяется втихую): продолжите её командой `/resume`.

## Файлы на сервере

`~/.kvist/remote/<id>/` (или в `KVIST_CONFIG_DIR`), закрыты от других: `events.ndjson` (всё, что агент сказал своему
интерфейсу, `.1` — предыдущий), `sock` (сокет, к которому подключаются интерфейсы, читаем только вами), `daemon.lock`,
`daemon.json`, `daemon.log`. Журнал заменяется при старте демона и когда он перевалил за 64 МБ в конце хода, при
котором никто не подключён. Сама беседа лежит, как всегда, в `.kvist/sessions/` папки.

## Интерфейсы

| Интерфейс | Состояние |
|---|---|
| Ink (`tui`, `claude`) | работает: баннер, перехват, состояние связи, `/remote`; видели в настоящем терминале на настоящем ядре |
| Терминал OpenCode | баннер и перехват из общего кода; проверено тестами, в терминале не видели; `/remote` нет |
| VS Code | настройки `kvist.remote.host` и `kvist.remote.workspace`; баннер и перехват в панели; в VS Code не запускали |
| JetBrains | обрабатывает сообщение перехвата; настройки выбора сервера нет; не запускали |
| Classic (`glass`), Voice | баннер (в Voice Enter перехватывает, речь и ввод пока отклоняются); проверено тестами, в kitty не видели |
| Пиксельное приложение (Tauri), Electron | показывают баннер и перехватывают; выбрать сервер из них нельзя |
| Classic Legacy, Zed (ACP) | не поддерживаются: агент работает внутри них |

## Ограничения, честно

- Windows сервером быть не может. Windows-компьютеру как *интерфейсу* нужен только `ssh.exe`; не пробовали.
- Ветки macOS и BSD (LaunchAgent, crontab, пути `AF_UNIX`) покрыты только тестами текста и на этих системах не
  запускались.
- Подтверждения, на которые некому ответить, ждут вечно. Авторежим (`/permissions auto on`) решает их без вас, с тем
  же предупреждением, что и везде.
- Экраны настроек интерфейса (провайдеры, ключи) по-прежнему правят конфигурацию вашего компьютера, а не сервера.
  Серверную меняйте через `ssh -t HOST kvist-core`.
- `--resume`, `--role`, `--provider` и подмена моделей до работающего демона не доходят; он держит то, с чем
  стартовал.
