# Конфигурация и поведение

Справочник по настройкам, провайдерам, песочнице и headless-режиму. Что такое
Kvist и как её установить, написано в [README](../README.ru.md).

Глобальные настройки лежат в `~/.kvist/config.json`; `KVIST_CONFIG_DIR` переносит
файл в другую папку. Состояние проекта хранится в `<workspace>/.kvist/` (сессии,
журнал изменений, логи, `permissions.json`). Не коммитьте ни то, ни другое.

## Провайдеры

`/provider` выбирает и настраивает провайдера. Доступны:

- AnyModel (по умолчанию при пустом конфиге), OpenAI, Anthropic, DeepSeek,
  OpenRouter, OmniRoute (локальный OpenAI-совместимый шлюз на
  `http://localhost:20128/v1`) и FreeFlow LLM (beta);
- ChatGPT Plus/Pro через вход в браузере, без API-ключа;
- 36 других OpenAI-совместимых сервисов (Qwen, Moonshot, Mistral, Groq, xAI,
  Together, Cohere и другие; полный список — `MANUAL_OPENAI_PROVIDERS` в
  `kernel/llm_clients.py`);
- любой свой endpoint, совместимый с OpenAI или Anthropic.

У каждого провайдера есть **fast**-модель для обычных шагов и **smart**-модель
для сложных задач, ошибок разбора и застоев. Выбираются через `/models`.
`/change-api` заменяет ключ. `AGENT_LLM_PROVIDER` переопределяет сохранённого
провайдера на один запуск.

### AnyModel

Если задан `ANYMODEL_API_KEY`, Kvist стартует без вопросов. Иначе первый запуск
показывает экран: Enter открывает страницу регистрации и просит ключ, Esc ведёт
к списку провайдеров. Ключ сразу проверяется по каталогу AnyModel, поэтому
неверный ключ отклоняется на месте. Тот же endpoint отдаёт коэффициент биллинга
по моделям, на нём строится подсчёт стоимости:

```bash
curl -H "Authorization: Bearer $ANYMODEL_API_KEY" https://anymodel.org/v1/models
```

### ChatGPT Plus/Pro

Выберите **ChatGPT Plus/Pro** в `/provider` (id `chatgpt`) или в настройках
провайдера в веб-клиенте или десктопном приложении и нажмите **Continue with
ChatGPT**. В системном браузере откроется страница входа OpenAI. Нужна
подходящая подписка Plus или Pro и разрешение использовать её лимиты для Kvist.
API-ключ OpenAI не нужен.

Kvist следует открытой схеме Sign in with ChatGPT от OpenAI: динамическая
регистрация клиента, authorization code с PKCE и временный callback
`http://127.0.0.1:<port>/auth/callback`. Слушатель привязан только к loopback и
закрывается после успеха, отмены или через три минуты. Токены хранятся в секции
`chatgpt_oauth` файла `~/.kvist/config.json` (атомарная запись, права `0600` в
Unix). Kvist не импортирует учётные данные Codex или OpenCode, а OAuth-данные
исключены из синхронизации настроек, поэтому входить нужно на каждом компьютере.
На удалённом сервере входите на нём самом.

Запросы идут на `https://api.openai.com/v1/responses` с `store=false`. Ответ
считается полным только после `response.completed`; оборванные потоки и
исчерпание лимита плана показываются как ошибки. Запросы несут стабильный
`prompt_cache_key`, чтобы поддерживаемые модели переиспользовали неизменный
префикс, а число кэшированных токенов из ответа сервера сохраняется в учёте
использования. Кэш не отменяет запросы, и кэшированный ввод по-прежнему входит в
лимиты скорости. Из того же ключа выводятся заголовки `session-id`, `thread-id` и
`x-client-request-id`: без них бэкенд раскидывает запросы по разным машинам, и кэш
почти не срабатывает.

Расход идёт из вашего плана ChatGPT и делится с другими приложениями, которые его
используют. Лимиты смотрите в
[ChatGPT Settings, Usage](https://chatgpt.com/settings/usage). Ваши разговоры в
ChatGPT Kvist прочитать не может. `/change-api` запускает повторную авторизацию.
Headless-операции принимают JSON:

```bash
python -m kernel --config-op chatgpt-login --config-payload '{}'     # вход в браузере
python -m kernel --config-op chatgpt-accounts --config-payload '{}'  # учётные записи, без токенов
python -m kernel --config-op chatgpt-logout --config-payload '{}'    # отозвать сессию
# {"new":true} добавляет аккаунт; {"account":"<id>"} выбирает или переавторизует аккаунт.
```

Если удалённый отзыв подтвердить нельзя, Kvist выходит локально и просит
отключить приложение в ChatGPT Settings.

## Модели, контекст и рассуждения

**Бюджет контекста.** Размер промпта берётся из документированного максимума
*входа* активной модели (`kernel/context_budget.py`), а не из её окна контекста.
OpenAI резервирует 128k окна под вывод, поэтому модель GPT-5 с окном 400k
отклоняет промпты длиннее 272k; Anthropic ограничивает только вход. Бюджет равен
85% лимита входа, потому что tiktoken занижает счёт для токенизаторов Anthropic
и DeepSeek: модель на 1M получает 850k, на 272k — 231k. Модели новее встроенной
таблицы наследуют лимит своего семейства. Если провайдер всё же отклонил промпт
как слишком длинный, Kvist снижает бюджет для этой модели и отправляет заново.
`AGENT_MAX_CONTEXT_TOKENS` задаёт значение вручную. `/context` показывает
текущее заполнение.

**`/settings-api`** меняет настройки транспорта, которые хранятся в `api_settings`
конфига: минимальный интервал между запросами, таймаут, число ретраев и backoff,
бюджет промпта (`auto`, `1m`, `250k`), загрузку каталога моделей из `/v1/models`
при запуске, кэш ответов внутри запуска и фолбэки моделей. Сохраняются только
значения, отличающиеся от умолчаний. `AGENT_API_INTERVAL` и
`AGENT_MAX_CONTEXT_TOKENS` приоритетнее сохранённых значений.

**Глубина рассуждений.** `/effort` задаёт `false`, `low`, `medium` (по умолчанию),
`high`, `xhigh` или `max`, а Kvist переводит значение под каждого провайдера.
DeepSeek сводит `medium` и `xhigh` к `high`; `/effort false` отключает
размышления. Высокий уровень не гарантирует меньше вызовов инструментов или
лучший результат. Если провайдер отклоняет настройку, Kvist повторяет запрос без
неё и предупреждает. `AGENT_REASONING_EFFORT` переопределяет сохранённый уровень
на один запуск.

**Нативные вызовы инструментов.** На первой задаче запуска Kvist отправляет один
небольшой запрос и проверяет, вызывает ли модель инструменты нативно. Если да,
запуск идёт одним растущим разговором из вызовов и результатов. Если нет или если
провайдер отказывается от инструментов посреди запуска, используется JSON-протокол
Kvist. `AGENT_NATIVE_TOOLS=0` включает JSON-протокол принудительно.

## Сессии

Имя сессии состоит из 1–64 строчных букв, цифр, `-` или `_` и начинается с буквы
или цифры. У каждой сессии свои история и checkpoint. Каждый запуск начинает
новую сессию; `/new` делает то же, а прежняя остаётся доступной через
`/session`. Checkpoint пишется после каждого шага, который что-то меняет, и после
каждой пачки чтений, поэтому `/resume` продолжает прерванный запуск. Журнал
изменений, на котором держатся `/changes` и `/revert`, общий для всего workspace
и восстанавливает файл, только если его текущее содержимое записала Kvist.

## Песочница и разрешения

Запись и shell-команды ограничены workspace. Действия только для чтения могут
использовать дополнительные каталоги из повторяемого `--allow-read DIR`.

- **Linux.** Команды работают в Bubblewrap с отдельными HOME и `/tmp`, скрытыми
  `/home` и `/root`, замаскированными секретными путями и без сети.
  `AGENT_SANDBOX_MODE` принимает `auto`, `workspace` или `bubblewrap`. Режим
  `workspace` слабее: без маскирования секретов и без изоляции `.kvist`.
- **macOS.** Офлайн-выполнение на хосте обеспечивает `/usr/bin/sandbox-exec`.
- **Windows.** Офлайн-режима на хосте нет. Команда, которой он нужен, отклоняется,
  а не запускается с сетью.

Команда может запросить два отдельных разрешения на один запуск: `sandbox: "host"`
(инструменты и файлы хоста) и `network: true`. Каждое требует обоснования и
отдельного подтверждения, правила allow проекта их не отменяют, запомнить их
нельзя. Режим хоста сохраняет отдельный HOME, очищенное окружение и проверку
команд и не даёт прав администратора.

В `<workspace>/.kvist/permissions.json` лежат шаблоны `allow`, `deny` и `ask`.
Правила deny и встроенные блокировки всегда приоритетнее. Если некому ответить
(нет терминала или клиента), подтверждения отклоняются. `fetch_url` открывает
известные сайты документации без вопросов; для любого другого сайта спрашивает
один раз: да, всегда да для этого сайта (сохраняется как `web_domains`) или нет.

## Файлы инструкций проекта

`KVIST.md` (coder, reader, devops) и `KVIST-CHAT.md` (chat) создаются из шаблона
в корне workspace при первом запуске и добавляются к системному промпту роли на
каждом шаге. Если в workspace есть `.gitignore`, оба имени однократно дописываются
в него; без `.gitignore` ничего не записывается.

Файлы принадлежат проекту, поэтому Kvist считает их недоверенными: они попадают в
промпт как ограниченный блок данных, а окружающие инструкции сводят их роль к
командам, устройству и конвенциям. Это затрудняет враждебный файл и делает его
заметнее, но не даёт гарантии. Настоящие границы — механизмы, которые не читают
промпт: проверка команд, маскирование секретов, границы workspace и подтверждения.

## Терминальные интерфейсы

Интерфейс Ink (`frontends/tui/ink/`, Node.js 22+) — отдельный процесс, который
управляет Python-ядром. Установщик из релиза приносит Node.js и собранный UI. Из
исходников:

```bash
(cd frontends/tui/ink && npm install && npm run build)   # frontends/tui/ink/dist-ui/kvist-tui.mjs
.venv/bin/python -m kernel --frontend tui      # Ink
.venv/bin/python -m kernel --frontend claude   # скин в стиле Claude Code того же приложения
.venv/bin/python -m kernel --frontend terminal # классический терминал
.venv/bin/python -m kernel --frontend voice    # экран голоса (kitty/Ghostty; сначала соберите, см. frontends/voice/README.ru.md)
```

`/tui` сохраняет выбор. Если нет Node.js, собранного файла, провайдера или TTY,
Kvist запускает классический терминал и сообщает причину. Скин в стиле Claude
работает на альтернативном экране, поэтому прокручивает ленту сам (`PgUp`/`PgDn`,
`Ctrl+Home`/`Ctrl+End`, колесо мыши) и забирает мышь: протяжка выделяет текст,
двойной клик — слово, тройной — строку, а `Shift` с протяжкой включает выделение
самого терминала. Белка в приветствии рисуется картинкой в терминалах с
графическим протоколом kitty или Sixel и блочными символами в остальных;
`KVIST_GLYPHS=octants` или `quadrants` задаёт выбор вручную.

Опасная команда или перезапись файла открывают экран подтверждения: стрелки или
1/2/3 для выбора, Esc для отказа. «Больше не спрашивать» сохраняет правило в
`permissions.json` и не предлагается для опасных команд. Enter отправляет, двойной
Esc или `Ctrl+C` останавливает запуск, `Ctrl+D` выходит.

## Headless-режим и протокол

Один раз настройте провайдера в терминале, затем управляйте Kvist из другого
процесса:

```bash
.venv/bin/python -m kernel --workspace /path/to/project --frontend stdio
```

Поток — JSON по одному объекту на строку. Первое событие — `hello`, затем статусы,
потоковый текст, запросы подтверждений, ошибки и итоговый ответ. Ответы на
`input_request` — JSON-объекты в stdin. Полный протокол описан в
[`UI_API.ru.md`](UI_API.ru.md).

```bash
.venv/bin/python -m kernel --workspace DIR --config-info             # сохранённые провайдер и модели, без вызова LLM
.venv/bin/python -m kernel --workspace DIR --session-op status       # также: create, switch, list
.venv/bin/python -m kernel --workspace DIR --journal-op changes      # также: revert
echo '{"files": [{"path": "app.py", "patch": "+print(1)"}]}' \
  | .venv/bin/python -m kernel --commit-message
```

Переопределения на один запуск: `--provider`, `--fast-model`, `--smart-model`
(обе модели указываются вместе), `--role`, `--approval-mode ask|deny`. `--resume`
продолжает активный checkpoint без чтения цели; `--resume SESSION_ID` выбирает
сессию по id (имя файла без `.json`).

## Переменные окружения

| Переменная | Действие |
| --- | --- |
| `AGENT_LLM_PROVIDER`, `AGENT_FAST_MODEL`, `AGENT_SMART_MODEL` | Провайдер и модели на один запуск |
| `AGENT_REASONING_EFFORT` | Глубина рассуждений на один запуск |
| `AGENT_MAX_STEPS` | Число шагов, после которого Kvist спрашивает, продолжать ли (по умолчанию 150) |
| `AGENT_MAX_CONTEXT_TOKENS` | Задаёт бюджет промпта |
| `AGENT_NATIVE_TOOLS` | `0` включает JSON-протокол принудительно |
| `AGENT_SANDBOX_MODE`, `AGENT_SANDBOX_NET` | Тип песочницы и политика сети |
| `AGENT_VISION_MODEL` | Модель для изображений у того же провайдера |
| `AGENT_VOICE_MODE` | `1` для голосового фронтенда: короткие ответы вслух и рассказчик, пока думает сильная модель |
| `AGENT_VERBOSE`, `AGENT_PERSIST_LOGS` | Диагностика и логи запусков |

Для интерактивной настройки используйте `/provider`, `/models`, `/role` и
`/effort`.
