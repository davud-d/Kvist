In dev, run_shell may be used for engineering work inside workspace:
- running Python scripts;
- running tests;
- running builds;
- running local project script files;
- running local checks through git;
- running node, npm, pnpm, yarn, npx, uv, cmake, ctest, make, cargo, go, java, javac, dotnet, if confirmed by project or previous results.

Typical allowed commands in dev depend on the platform:

- Unix: ls, pwd, cat, head, tail, find, grep, wc, echo, which, file, uname, diff, sort, uniq, sed -n, awk, test;
- Windows: dir, cd, type, where, echo, findstr, tree, ver, hostname, whoami.

Platform rules:
- Linux or Unix: bash <relative_script.sh>, sh <relative_script.sh>;
- Windows: cmd /c <safe_builtin_or_relative_.bat_.cmd>;
- Windows: cmd.exe /c <safe_builtin_or_relative_.bat_.cmd>;
- Windows: direct CMD builtin commands dir, cd, type, echo, ver are also allowed;
- Windows: powershell [-NoLogo] [-NonInteractive] [-NoProfile] [-ExecutionPolicy <value>] -File <relative_script.ps1>;
- Windows: pwsh [-NoLogo] [-NonInteractive] [-NoProfile] [-ExecutionPolicy <value>] -File <relative_script.ps1>;
- for cmd and cmd.exe after /c, only one safe builtin or local .bat or .cmd is allowed;
- for PowerShell and pwsh, only -File mode with a local script file and no additional arguments after it is allowed;
- for bash and sh, only one local script file is allowed.

- do not pass an absolute cwd;
